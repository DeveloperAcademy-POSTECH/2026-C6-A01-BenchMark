# PR #151 검색 화면 후속 검증 — 2026-11-05

## 변경

검색 진입 전에는 캐릭터가 생략되고, 검색을 실행해 0건이 된 뒤에만 표시되던 분기를 수정했다. 이름·기부자·코드 검색은 처음부터 Figma의 `CampusSearchNoResults` 원본 캐릭터와 입력 안내를 표시한다. 실제 검색 성공 0건일 때는 Figma 문구로 바뀐다. 오류·로딩·결과 목록은 별도 상태다.

기부자 검색은 사용자 요청에 따라 학교·학과·학번·이름 네 항목이다. 입력한 조건은 AND로 결합한다. 학번은 입학연도로 다루며 26·2026·26학번을 동일하게 검색한다. 작성자 학교를 사용하고 배치 캠퍼스나 닉네임을 대신 사용하지 않는다.

## 검증

- Xcode 27.2, iPhone 18 Pro Simulator(iOS 27.2), OiFlowChecks, CODE_SIGNING_ALLOWED=NO.
- 상태 분리·검색 전후 캡처·프로필 저장/삭제/재실행·기존 프로필 수정 회귀: 선택한 XCTest 6개 통과. 최종 여백·툴바 보완 뒤 캡처 XCTest 2개 재실행 통과.
- `sh apps/ios/Tests/run-campus-checks.sh`: 네 항목 검색, 입학연도 표기, 누락 정보 및 닉네임 대체 금지 검사 통과.
- `sh apps/ios/Tests/run-oi-service-checks.sh`: 기존 서버 응답 호환성 및 API 검사 통과.
- `python3 supabase/tests/run-account-merge-db-checks.py`: 임시 PostgreSQL에 마이그레이션 적용, 소유자만 수정, 비공개 작성자 숨김, 공개 작성자 조회, 전체 학생번호 거부, 기존 계정 통합 회귀 통과. 테스트 서버 종료 확인.
- 실제 iPhone 및 운영 DB에서의 저장·검색은 아직 검증하지 않았다.

## 서버 적용 순서

1. 기존 팀 DB에 `supabase/migrations/20261105090000_oi_public_donor_search.sql`을 마이그레이션으로 적용한다. 이 PR 작업 중 운영 DB에는 적용하지 않았다.
2. 앱 설정 → 학적정보에서 학교를 선택한다.
3. 설정 → 학적정보 → 기부자 검색 정보에서 공개할 이름·학과·입학연도를 저장한다. 빈 값으로 저장하면 해당 정보를 지운다.
4. 공개 이야기가 있는 작성자의 데이터를 검색한다. 미입력 항목은 추정하지 않으므로 그 조건으로는 일치하지 않는다. 증빙이나 Auth 메타데이터에서 자동으로 가져오지 않는다.

새 필드는 추가만 하며 기존 닉네임을 보존한다. 이전 DB 응답은 optional 디코딩으로 읽지만 새 검색 정보를 저장하려면 마이그레이션이 먼저 필요하다. 앱 전체 닉네임 제거는 이 PR의 검색 변경 범위를 벗어난 후속 작업이다.
