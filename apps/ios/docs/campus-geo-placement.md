# 캠퍼스 좌표 배치와 현장 AR 실험 (#96)

2026-10-27. PR #93의 캠퍼스 홈과 지도/AR 렌더러 전환 수정 위에서 작업했다. 이후 같은 #96에서 기존 `apps/web` 공용 저장 API·운영자 작성 승인·공개 조회 연결을 추가했다. **운영 배포는 팀원 계정 접근 문제로 미완료**다. [공유 모드 설정·API·배포 인계](../../../docs/campus-server-handoff.md)를 먼저 참고한다. 아래 사용법은 별도 메뉴로 유지한 **기기 예시 테스트**와 공통 좌표/AR 엔진 설명이다.

## 사용 방법

1. 홈 우측 메뉴에서 ‘기기 예시 테스트’를 선택한 뒤 ‘예시 오이 배치’를 누른다. 한 손가락으로 지도를 이동하고, 핀치로 확대·축소하며, 두 손가락으로 회전·기울기를 조절한다.
2. 지도 바닥을 탭한다. 캠퍼스 경계 밖과 건물 평면 내부는 거절한다. 실제 접근 가능성까지 판단하는 것은 아니므로 현장에서 이용 가능한 바깥 공간을 선택한다.
3. 바닥을 처음 선택하면 위에서 내려다보는 확대 화면으로 이동한다. 배치·수정 중에는 주변 오이와 초안을 실제 축척으로 표시하며, 발밑 1m 십자의 중심이 저장 지점이다. ‘위에서 보기’/‘주변 보기’, 화면 방향에 맞는 10cm·50cm·1m 이동으로 위치를 조정한다. 키·방향 항목을 펼쳐 실제 높이(0.4~2m)와 북쪽 기준 방향을 설정한다. 저장·취소 후 탐색에서는 식별용 20배 심벌로 돌아온다. AR은 저장된 실제 높이를 사용한다.
4. 저장한 3D 오이를 누르면 ‘배치한 오이’ 메뉴에서 이야기 보기·현장 AR·위치 수정·삭제를 선택한다. ‘기기 저장’ 목록에서도 위치 수정·삭제·현장 AR 버튼을 사용할 수 있다.
5. 실제 캠퍼스의 해당 지점에서 카메라·정확한 위치를 허용한다. 시험용 조건은 목표 25m 이내, GPS 수평 오차 15m 이하, 위치 샘플의 시각 차이 10초 미만이다. 이 숫자는 수집 정책이나 정확도 보장이 아니다.
6. AR 오이를 탭하면 같은 storyID의 상세 이야기를 연다. 이야기를 닫으면 위치와 AR을 다시 확인한다. 보정은 새 AR 세션에서 다시 진행한다. 기존 홈의 일반 AR 카메라는 그대로 사용할 수 있다.

## 좌표 기준

- `campus-data.json`: 원점 `[경도 129.32, 위도 36.017]`, `unitsPerMeter = 0.12`, `WGS84_ENU_XY_V06` 좌표계.
- 지도 선택: 화면 ray → `CampusHeightField.intersect` → 건물/경계 검사 → `CampusMapData.coordinate` → WGS84 위도/경도.
- 지도 복원: WGS84 → `CampusMapData.world` → 지형 높이 보간. RealityKit 지도 축은 +X 동쪽, +Y 위쪽, -Z 북쪽이다.
- AR: 월드 단위는 미터이므로 지도 축척 0.12를 적용하지 않는다. GPS 모드는 현재 위도/경도 기준 WGS84 ENU 오프셋과 `.gravityAndHeading` 프레임을 사용한다.
- 지도 지형은 추정 높이다. AR 지리 고도로 전달하지 않는다. 좌표 왕복 테스트 통과는 산술 정확성 확인이며 실제 지도 정합·측량 정확도 검증이 아니다.
- 미세 이동은 지도 축척 0.12와 카메라 yaw를 적용한 수평 거리다. 매번 지형 높이를 다시 구하고 건물 내부·경계 밖·지형 없는 위치를 거절한다. 10cm 조작 단위는 GPS나 지도 원본이 10cm 정확하다는 의미가 아니다.

## AR의 세 가지 모드

| 모드 | 동작과 한계 |
| --- | --- |
| 지리 추적 | 기기 지원과 대상 좌표 `checkAvailability`를 확인한다. ARKit 위치 보정이 localized 및 medium/high 정확도일 때, 고도를 지정하지 않은 ARGeoAnchor로 지면에 배치한다. 지역·네트워크·기기 조건에 따라 사용할 수 없다. |
| GPS 근사 배치 | GPS와 나침반 기준으로 대상 X/Z를 추정하고 현재 주변에서 인식한 수평 바닥의 Y를 사용한다. 목표 지점의 지형 높이를 측정하는 것이 아니므로 경사·계단에서는 높이 오차가 생긴다. 최초 배치 후 GPS 흔들림을 매 프레임 적용하지 않는다. |
| 직접 바닥 보정 | 목표 주변의 실제 지점을 사용자가 탭한다. 인식된 수평 바닥에 배치하고 저장된 방향을 적용한다. 새 좌표를 저장하거나 GPS 정확도를 높이는 기능이 아니며 현재 세션에만 적용한다. |

거리·위치 최신성·카메라 추적이 불량하면 오이를 숨기고 복구를 안내한다. 권한 거절, 앱 비활성화, 추적 중단·오류를 처리한다. 지리 추적 확인이 지연되면 사용자가 GPS/바닥 모드로 전환할 수 있고 오래된 확인 콜백은 무시한다. AR→이야기→AR에서는 세션을 재확인한다. 이 화면은 현장 위치/이야기 실험이며 촬영·손바닥 모드는 기존 일반 AR 카메라에 남아 있다.

## 저장과 서버

`CampusPlacementRepository`와 `CampusPlacementStore`를 분리했다. 현재 `LocalCampusPlacementRepository`는 앱 Application Support의 `OiDonation/campus-placements-v1.json`에 schemaVersion과 최대 20개의 배치를 원자적으로 저장한다. 저장 성공 후에만 화면 상태를 갱신한다. 손상 파일은 덮어쓰지 않는다. ID, storyID, 위도/경도, 실제 높이, 방향, 모델 키를 저장한다. 위치 실험은 현재 기기에서만 보이고 증빙 승인이나 공개 글 작성 권한을 부여하지 않는다.

`apps/web`의 Next.js/PostgreSQL 서버에는 이제 `/api/campus/*`와 `/admin/campus`가 구현돼 있다. `CampusSharedAPI`/`CampusSharedStore`가 비동기 네트워크·인증·실제 이야기 상태를 담당하며 기기 테스트 저장소와 분리한다. `AppContainer.pilot`의 예전 명패 Repository를 운영 저장소로 바꾼 것이 아니다. 실제 공개 URL은 아직 미설정이다. [배포·기능 범위](../../../docs/campus-server-handoff.md)를 참고한다.

별도 로컬 프로젝트 `oi-campus-prototype`에는 `https://oi-postech-campus.tinyslug64.chatgpt.site/` 서버 주소와 `app/api/placements/route.ts`가 있다. 확인한 소스 기준:

- GET/POST는 `getChatGPTUser` 기반 웹 세션을 요구하고 D1에서 owner별 데이터를 조회한다.
- `shared/placement.mjs`는 학술정보관 주변 150m만 허용한다. 새 앱의 전체 캠퍼스 정책과 다르다.
- 레코드에 새 앱의 storyID/운영자 승인·공개 권한 계약이 없다. 웹 클라이언트의 이전 좌표 변환도 최신 iOS ENU 변환과 다르다.
- URL과 코드의 존재를 확인한 것이며 현재 서버 가동·계정 접근·iOS API 인증을 검증하거나 변경한 것은 아니다.

이전 웹 프로토타입은 그대로 유지했다. 새 공유 API는 저장소의 기존 돗자리 웹 서버를 확장한다. 운영 DB 자체를 조회·배포하지 않았으며, 공개 서비스 연결은 소유 팀원의 배포 후 검증해야 한다.

## 모델과 기존 기능

`Resources/Characters/helmet-oi.usdz`는 기존 `oi-campus-prototype/ios/OiCampusAR/OiCampusAR/Resources/helmet-oi.usdz`의 안전모 오이를 재사용했다. 로딩 시 발 위치를 원점으로 정렬하고 높이 1m로 정규화한 후 지도/AR에서 clone한다. 신규 자산은 전체 앱만 포함하며 App Clip 대상에는 추가하지 않았다. 이전 AR 캐릭터·회전·핀치·손바닥·조명·그림자·촬영 구현은 변경하지 않았다. 개인 서명 설정도 변경하지 않았다.

## 현장 AR 복귀 후 지도 확대·축소 — 2026-10-27

현장 AR을 닫은 뒤 핀치하면 건물은 그대로인데 초록색 지역 마커만 이동하는 현상이 보고됐다. AR 진입에서 해제한 non-AR `ARView`의 앵커·카메라 엔티티를 새 렌더러에 재연결하던 경로를 변경했다. 복귀 때 새 앵커·카메라·조명·지도 엔티티를 구성하고, 저장한 확대율·방향·지도 중심·배치 레코드와 초안으로 화면을 복원한다. 메쉬·오이 자산 템플릿은 재사용하지만 이전 렌더러의 엔티티 그래프는 옮기지 않는다. 일반 스토리 이동은 기존처럼 렌더러를 유지한다.

Debug 실행 인자 `-campus-renderer-check`는 카메라 권한이 허용된 실기기에서 지도 축소 전후의 실제 렌더링 이미지와 카메라 위치를 비교한다. 최초 화면과 AR 세션 전환 세 번 뒤를 검사하며, 단순히 핀치 변수만 바뀌는 상태를 통과로 처리하지 않는다. 이 개발용 검사와 별도로 ‘기기 예시 배치 → 현장 AR → 닫기 → 핀치’, 일반 촬영 카메라 복귀, 스토리 상세 복귀를 손으로 확인한다. 이 검사는 GPS 위치 정확도나 운영 서버 연결을 검증하는 것이 아니다.

검증: Jun iPhone용 Debug 빌드, 좌표·저장 2,081건 검사와 스토리 검사 통과. 실제 iPhone에서 첫 화면 및 AR 전환 3회 후 축소 이미지 차이 약 6.9%, 렌더러와 제어 카메라의 위치 차이 0을 확인했다. 사용자가 ‘오이 배치 → 저장 목록의 현장 AR → 닫기 → 핀치’ 경로에서 이제 건물과 초록색 숫자 표시가 함께 확대·축소된다고 확인했다. 이번 수정 후 일반 촬영 카메라·상세 화면의 수동 재검증은 별도이며, 기존 검증 기록과 구분한다.

## 배치 위치 수정·삭제 — 2026-10-27

- 기기 예시의 지도 오이 또는 저장 목록 → **위치 수정** → 지도 바닥을 탭 → **변경한 위치 저장**. 같은 ID와 스토리를 유지하며 새 오이를 추가하지 않는다. 기존 키·방향을 불러오고 필요하면 조절할 수 있다.
- 이동 중에는 원본을 잠시 숨기고 초안만 표시한다. 취소하면 저장하지 않고 원본을 다시 표시한다. 캠퍼스 밖·건물 안 좌표는 기존처럼 거절하며 저장 실패 시 원래 데이터와 편집 화면을 유지한다.
- 기기 오이 삭제는 확인 후 선택한 ID만 저장소·지도에서 제거한다. 연결된 예시 이야기나 수집 기록을 지우지 않는다. 목록 스와이프도 같은 확인 창을 사용한다.
- 공유 모드에서는 기존 ‘내가 쓴 오이’ 목록에 더해, 지도에서 본인 오이를 선택한 상세 화면에도 위치·내용 수정과 삭제를 제공한다. API의 소유권·revision 검증을 유지하며 위치 수정도 공개 검토 대기로 돌아간다. 공유 오이 삭제는 그 오이와 이야기를 함께 삭제한다. 실제 서버 배포·연결 전에는 기기 예시로 확인한다.
- 수정 또는 AR로 이동할 때 선택 메뉴가 완전히 닫힌 뒤 다음 화면을 연다. 앞서 수정한 지도 렌더러 복귀 처리를 유지한다.
- 검사: 수정 후 ID·스토리·순서·개수 유지, 앱 재실행 후 좌표 복원, 20개 한도에서도 수정 가능, 없는 ID 재생성 방지, 잘못된 위치·파일 쓰기 실패 시 원본 보존, 선택한 ID만 삭제·복원을 자동 검사했다.
- iPhone용 Debug 빌드와 기존 캠퍼스 스토리·수집 검사도 통과했으며 Jun iPhone에 설치·실행했다. 사용자가 실기기에서 위치 수정과 삭제가 모두 정상 동작한다고 확인했다. 취소 후 원본 복원은 코드로 확인했으며 별도의 실기기 확인은 하지 않았다. 공유 서버에서의 실제 수정·삭제는 배포·연결 후 검증해야 한다.

## 실제 축척 편집과 위치 오차 안내 — 2026-10-27

- 이번 변경은 선택 UI의 20배 과장과 확대 한계를 개선한다. 지도 원점·축척·원본 건물 위치 및 기존 저장 좌표를 임의로 변경하지 않는다. 캠퍼스 기준점 측량 자료가 없어 실제 지도 정합을 보정했다고 주장하지 않는다.
- 사용자 요청에 따라 현장 기준 이미지 인식은 추가하지 않는다. 기존 ARGeoTracking 지원 확인/GPS 근사/세션 내 수동 바닥 보정을 유지한다. 현장 화면에는 GPS 불확실성 반경, 근접 조건 충족과 정확도 보장의 차이, 주변 바닥으로 목표 높이를 추정하는 한계를 표시한다.
- 자동 검사는 실제 미터 축척, 회전한 카메라에서의 10/50/100cm 이동, WGS84 방향, 지형 높이 재계산, 경계·건물·비정상 입력 거절과 기존 저장·수정·삭제를 포함한다.
- Debug 실행 인자 `-campus-placement-check`는 저장소를 수정하지 않는 초안으로 모델 높이·좌표 유지·미세 이동·렌더러 재생성 후 발 위치/십자 복원·취소를 검사하고 미저장 편집 화면을 남긴다. 측량이나 GPS 센서 정확도를 검증하는 테스트는 아니다.
- 현장 검증은 여러 기준점의 실제/모델 위치 차이와 AR 배치 오차를 각각 측정해야 한다. 휴대폰 GPS 한 번의 좌표를 정밀 측량 기준으로 사용하지 않는다.
- 검증 결과: iPhone/Simulator Debug 빌드, 좌표·이동·저장 검사 2,081개 좌표 왕복 및 기존 스토리 검사 통과. 시뮬레이터 런타임에서 실제 2m 모델 높이, 크기 변경 시 좌표 유지, 회전 후 10cm 이동, 렌더러 재생성 후 초안·십자 복원, 취소를 확인했다. 화면에서 이동 버튼의 좌표 변경과 주변 보기·키/방향 펼침·취소 후 재진입을 확인했다. 현장 GPS 정확도와 공유 운영 서버 연결은 이 검증에 포함하지 않는다.

최종 Debug 빌드를 Jun iPhone의 기존 `com.Spero.OiDonation` 앱에 업데이트 설치하고 정상 실행했다. 프로젝트/Info.plist의 개인 서명 설정은 작업 시작 전과 동일하게 유지했다. 실제 캠퍼스에서 배치 오차가 줄었는지는 아직 측정하지 않았다.
