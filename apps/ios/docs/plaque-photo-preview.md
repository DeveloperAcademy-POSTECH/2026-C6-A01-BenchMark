# 벤치 사진 기반 명패 미리보기 — #73

- 구현일: 2026-10-14
- 브랜치: `feat/#73-bench-plaque-preview`
- 현재 실행 중인 #72 AR 경기장 기능을 유지한 후속 브랜치다. 기준 develop(`5669ca1`)과 선행 #72 커밋(`b1c52fd`)을 포함한다. develop 대상으로 통합할 때 선행 작업의 병합 여부를 확인한다.

## 앱 진입

- **후원 → 명패 미리보기**: 벤치 목록이나 서버 연결이 없어도 사진 합성 기능을 체험한다. 처음 표시하는 문구와 사진은 예시다.
- **후원 → 기부 시작하기 → 참여 신청 → 오래 남길 이야기**: 기존 `draft.message`를 확대 보기와 벤치 전체 보기에 연결한다. 새로운 참여·납입 상태나 명패 제공 기준을 만들지 않는다.
- **벤치 사진 선택**: PhotosPicker로 사용자가 선택한 사진 한 장만 가져온다. 전체 사진 보관함 접근 권한이나 서버 업로드는 사용하지 않는다.
- 사진을 가져온 뒤 **명패 부착 위치** 화면에서 네 모서리를 움직여 적용한다. 같은 화면의 가로·세로 슬라이더도 사용할 수 있다.
- **위치 조정**으로 다시 보정할 수 있다. 취소하면 기존 위치를 유지한다.

## 합성·갱신

1. 문구는 참여 신청과 동일하게 앞뒤 공백을 정리한다. 한글과 줄바꿈을 보존한다.
2. Core Graphics/Core Text로 명패의 배경·문구를 하나의 1020×330px 이미지로 그린다. 이 비율은 170×55mm 디자인 후보이며 실제 제작 사양이 아니다.
3. 확대 보기는 이 이미지 자체를 사용한다.
4. Core Image의 `CIPerspectiveTransform`으로 사진별 네 모서리에 맞추고 실제 사진 위에 합성한다. 원본 사진의 형상과 배경은 바꾸지 않는다.
5. 두 이미지는 한 결과 객체로 동시에 갱신한다. 문자열·사진·위치 변경은 `.task(id:)`를 재시작하고, 80ms 입력 병합 후 직렬 renderer actor에서 처리한다. 오래되거나 취소된 결과는 화면에 게시하지 않는다.
6. 긴 문구는 글꼴 크기를 줄여 맞춰 본다. 최소 크기에서도 전체 문구를 표시하지 못하면 오류를 안내하며 잘린 문구를 완성된 명패처럼 보여주지 않는다. 2000자는 미리보기 연산 보호 한도이며 학교의 문구 정책을 뜻하지 않는다.
7. 빈 문구는 ‘오래 남길 이야기를 입력해 주세요’라는 안내 예시로 표시한다. 참여 신청의 실제 문구에는 넣지 않는다.

## 벤치별 사진 설정

`Bench.plaquePreview`는 선택적인 `BenchPlaquePreview`다. 기존 Bench 생성자와 미연결 저장소는 계속 동작한다.

```swift
BenchPlaquePreview(
    assetName: "ApprovedBenchPhoto", // 실제 해당 벤치 사진을 앱 에셋에 등록
    photoVersion: "2026-10-14-front-v1",
    placement: PlaquePhotoPlacement(
        topLeft: .init(x: 0.30, y: 0.40),
        topRight: .init(x: 0.70, y: 0.42),
        bottomRight: .init(x: 0.70, y: 0.55),
        bottomLeft: .init(x: 0.30, y: 0.53)
    )
)
```

좌표는 **해당 사진의 왼쪽 위 기준 0~1**이다. 사진이 바뀌면 같은 좌표를 재사용하지 않고 사진 버전과 부착 영역을 함께 변경한다. 학교 벤치 사진·승인 위치 데이터는 현재 없으므로 운영 목록에 가짜 벤치를 추가하지 않았다.

기본 체험은 기존 `HomeBench` 사진을 벤치 주변으로 잘라 사용한다. 화면에서 ‘실제 POSTECH 벤치가 아닌 예시’라고 표시한다. 등록 사진이 없는 경우 이 예시를 사용하고, 등록된 사진 리소스가 잘못된 경우에는 사진을 불러올 수 없다고 안내한다.

사용자가 고른 사진과 조정한 위치는 현재 화면의 임시 미리보기 상태다. 서버·참여 신청·학교 승인 위치에 저장하지 않는다. 실제 운영은 벤치별 사진과 학교 승인 위치·규격을 공급하고, 사진/설정의 버전·저장·검수 계약을 마련해야 한다.

## 사진과 위치 검증

- 사진은 EXIF 방향을 반영하고 긴 변 2048px 이하로 읽는다. 30MB 초과 또는 지원되지 않는 이미지는 오류를 안내한다.
- 부착 영역은 범위 밖·NaN·겹침·면적이 없는 사각형을 거부한다. 편집 화면은 유효한 좌표만 적용한다.
- 이미지에는 미리보기 문구가 그려지지만 제출 데이터는 기존 `draft.message`가 원본이다. 미리보기 표시가 승인·납입 완료·명패 자격을 의미하지 않는다.
- 사진만으로 실제 mm 크기를 알아낼 수 없다. 운영자는 실측 또는 같은 규격의 종이 모형을 이용해 좌표를 보정해야 한다.
- 평면 명패를 가정한다. 사진 속 사람·팔걸이가 명패를 가리는 경우를 자동 처리하거나, 금속 반사·실제 조명을 재현하는 기능은 포함하지 않는다.

## 검증

- `sh apps/ios/Tests/run-plaque-preview-checks.sh`: 좌표의 유효성/JSON 복원, 사진 불러오기·오류·해상도 제한, 정확한 한글·줄바꿈, 문구 변경 시 두 이미지 변경, 원본 사진 영역 보존, 빈/긴 문구 및 취소 검사.
- `sh apps/ios/Tests/run-architecture-checks.sh`: 기존 참여 신청·라우팅·중복 요청·학교 확인 대기 검증.
- iOS Simulator 빌드 통과. Simulator에서 후원 화면 진입, 실제 한글 키보드 입력에 따른 두 이미지의 동시 갱신, 위치 편집의 적용·취소 버튼과 좌표 초기화를 확인했다.
- 실제 POSTECH 벤치 사진의 좌표·물리적 크기·최종 학교 규격과 비교하는 현장 검증은 아직 하지 않았다.
