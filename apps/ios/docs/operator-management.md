## 청크 2: 이야기 목록·상세·공개 처리 (2026-11-04)

- 진입: 운영자 관리 → 이야기 검토. 검토 대기 / 공개 / 비공개 / 전체 필터를 제공하며 기본 선택은 검토 대기다. `oi_stories`의 pending/published/hidden만 등록일·ID 역순으로 조회한다. 기존 API의 200건 단위 페이지 조회를 재사용한다. draft/deleted는 검토 목록에서 제외한다.
- `OiOperatorStoriesModel`은 목록·필터·로딩·빈 상태·조회 오류를 소유한다. 선택한 ID를 별도의 상세 화면에 전달하므로 처리 후 필터에서 항목이 빠져도 결과 안내를 확인할 수 있다.
- `OiOperatorStoryModel`은 상세 조회·처리 중·확정 응답·동기화 경고·재조회 필요 상태를 소유한다. 상세는 서버에서 이야기와 첨부 사진을 다시 조회하고, 제목·본문·상태·오이 이름·작성자 닉네임·등록일·주제·감정·구역·위경도를 표시한다. 사진은 기존 5분 서명 URL과 사진 로딩/재시도 컴포넌트를 재사용한다.
- 조회·처리 직전에 기존 서버 `oi_capabilities`를 재확인하며, 계정 세대가 바뀐 응답은 반환/적용하지 않는다. 최종 권한과 revision 충돌은 기존 `review_story` 서버 검사가 판정한다. 새 RPC·마이그레이션·운영 배포는 없다.
- 공개 전 확인한 이야기 스냅샷의 ID·revision과 목표 상태를 전달한다. pending/hidden에서는 공개 승인, published에서는 비공개 전환만 제공한다. 별도의 이야기 반려·보완 정책은 추가하지 않는다.
- 처리 중 중복 호출을 화면 모델과 공용 저장소에서 차단한다. 충돌·응답 유실·기타 실패 후에는 처리 버튼을 잠그고 최신 내용 조회를 요구하며 자동 재전송하지 않는다. 새로 조회한 내용에 이전 확인창의 스냅샷을 재사용하지 않는다.
- 서버 확정 응답을 받으면 상세와 목록 필터, 공용 공개 이야기 상태를 먼저 갱신한다. 후속 공용 목록 동기화만 실패했다면 성공과 동기화 경고를 함께 표시하고 재조회 전 추가 결정을 차단한다. 상세 재조회로 확인한 최신 상태도 부모 목록에 반영한다.
- 증빙 검토·작성 승인·학교 공식 납입 확인과 이야기 공개는 서로 다르다고 안내한다. 이번 청크는 증빙·AI·감사 기록 메뉴를 연결하지 않는다.

검증은 가상 서버의 공개→비공개, 필터 이동, revision 충돌과 재확인, 응답 유실, 확정 후 동기화 실패, 권한 철회, 중복 요청, 이전 계정의 늦은 응답 및 목록/상세 렌더링을 대상으로 한다. 실제 운영 데이터에는 검토 요청을 보내지 않는다.
