# POSTECH 캠퍼스 홈 디자인 전환

적용일: 2026-10-26. 범위: 전체 iOS 앱의 홈·지역 탐색·오이 요약·스토리 상세 화면. App Clip과 기존 AR 구현은 교체하지 않는다.

GitHub 이슈: #92. 배포용 변경은 `develop` 기준으로 분리했다. 기존 로컬 브랜치의 App Clip 원격 콘텐츠 후속 작업(#79), 테스트 서버, 개인 서명 설정은 포함하지 않는다. 이 브랜치에서도 전체 앱 빌드·두 검사 스크립트 통과, 지도 마커 → 요약 → 상세의 즉시 전환 및 뒤로가기 복귀를 확인했다. 기존 develop 파일의 Swift 동시성·사용 중단 API 경고는 남아 있다.

## 지도와 화면 구조

- `App/RootTabView.swift`: 기존 이름을 유지한 루트 `NavigationStack`과 `CampusDestination` 등록, 공용 수집 상태, 공개 링크, AR 모달. 지도 마커·지역 목록·자세히보기는 같은 `NavigationPath`에 순서대로 추가한다.
- `Features/Home/HomeView.swift`: 전체/지역 지도, 정렬·목록 높이·프로필 메뉴 상태. 지도 마커 선택은 `onOpenStory` 콜백으로 루트에 전달하며, 요약용 별도 item destination 상태를 사용하지 않는다.
- `Features/Campus/Scene/CampusExploreScene.swift`: RealityKit non-AR 렌더러, 카메라·제스처, 3D 위치를 화면 좌표로 투영하는 터치 마커.
- `CampusSummaryView` → `CampusStoryDetailView`: ID 기반 경로를 push한다. 상세에서 뒤로 가면 실제 진입한 요약 화면으로 돌아가며, 프로필에서 열린 화면도 해당 스택으로 복귀한다.
- `CampusStoryStore`: 예시 이야기와 지역별 개수, 정렬, 로컬 수집 상태. 서버 데이터와 기존 Domain의 기부 기록을 대체하지 않는다.
- `CampusProfileMenu`: 기존 내 기부·후원·벤치·사진 테스트로 연결한다. 이전 화면의 비즈니스 로직은 유지한다.

기존 별도 프로젝트 `oi-campus-prototype/ios/OiCampusAR/OiCampusAR`의 `campus-mobile.oimesh`, `campus-data.json`, 지면 높이 필드 3개와 로더·좌표 변환 코드를 재사용했다. 약 21 MB의 모델은 전체 앱 `Resources/Campus`에만 둔다. App Clip은 이 폴더를 참조하지 않는다. 좌표는 OiCampus의 WGS84 ENU 변환과 지면 높이를 사용한다.

한 손가락으로 지도를 이동하고, 핀치로 확대·축소한다. 두 손가락 좌우 드래그는 방향을 회전하고, 상하 드래그는 내려다보는 각도를 약 20~80도로 조절한다. 두 손가락 비틀기 회전도 유지한다. 지도 제스처끼리만 동시 인식을 허용하고 변화량을 누적해 확대·회전·기울기가 서로 덮어쓰지 않게 한다. 손가락 수가 바뀌면 드래그 기준을 다시 잡아 카메라가 튀는 것을 방지한다. 마커에서 시작한 드래그도 처리하며 드래그가 시작되면 마커 탭은 취소한다.

숫자 마커는 지역 목록을, 개별 캐릭터는 이야기 요약을 연다. ‘이 지역 재검색’은 현재 지도에 투영된 이야기만 목록에 남기며, 거리순은 **사용자 GPS가 아닌 지도 중심**을 기준으로 한다. 지역을 다시 열면 필터가 해제된다. 모델 로딩 중 진행 표시와 실패 시 재시도를 제공한다.

## 예시 데이터의 경계

- Figma의 11·3·8·5·26·14개를 6개 지역에 배정해 목록과 지도 숫자를 일치시켰다.
- 캐릭터는 현재 투명 PNG 마커다. 캠퍼스 모델은 3D이지만 마커가 실제 3D 모델이거나 자율 보행하는 것은 아니다.
- 수집은 `campus.designExample.collectedIDs.v1` UserDefaults 키에 저장한다. 중복 터치는 한 번만 반영하며, 요약·상세·프로필이 같은 상태를 사용한다. 계정 간 동기화·실제 기부자 자격은 아직 연결하지 않았다.
- 학교·인물·날짜·기부 횟수는 디자인 예시다. 실제 공개 서비스에서는 동의·승인된 콘텐츠 API로 교체해야 한다.
- ‘이어서 기부하기’는 기존 공식 기부 절차 안내를 연다. 수집 기록은 기부 납입 증빙이 아니다.

캠퍼스 검사: 라우팅 ID 유일성, 지역별 목록·개수 일치, 정렬과 거리 미제공 시 안정적인 순서, 수집 중복 방지·재실행 복원. 기존 아키텍처 검사는 공개 링크·신청 검증·중복 요청·학교 확인 대기 상태를 다룬다.

2026-10-26 검증 결과:

- Xcode 27, iPhone 17 Pro / iOS 26.5 Simulator의 전체 앱 빌드 성공. 위 두 검사 스크립트 통과.
- 전체 지도 6개 지역 마커, 지역 목록, 요약 카드, 전체 스토리의 표시를 확인했다. 가로 넘침과 손글씨 글꼴 이름 오류를 수정했다.
- 상세에서 수집 → 뒤로가기 → 요약의 ‘수집 완료’, 앱 재실행 후 프로필의 수집 1개 표시를 확인했다.
- 프로필의 수집 목록 → 스토리 상세 → 뒤로가기 시 동일한 프로필 목록으로 복귀하는 것을 확인했다.
- 사용자가 시뮬레이터에서 직접 하단까지 스크롤하여 갤러리·위치·기부자 소개가 정상 표시됨을 확인했다. 이 항목은 자동 드래그 도구의 제한으로 사용자 확인 결과를 기록했다.
- ‘이어서 기부하기’가 POSTECH 공식 절차 안내를 여는 것을 확인했다.
- 빌드 산출물의 App Clip에 `campus-*` 자산이 없으며, 작업 전후 개인 서명·entitlement·프로비저닝 관련 프로젝트 변경분이 그대로 보존됐음을 비교했다.

실제 iPhone의 프레임 속도·메모리, AR 촬영·NFC는 이 디자인 변경에서 재검증하지 않았다. 개인 서명 설정과 프로비저닝 프로파일은 변경하지 않는다.

같은 날 두 손가락 드래그 회전·기울기 조절을 추가한 뒤 iPhone 17 Pro / iOS 26.5 Simulator 빌드가 성공했다. 실제 멀티터치 조작감과 손가락 수 전환·마커 위 드래그 동작은 실기기에서 추가 확인해야 한다.

같은 날 지도 마커에서 요약을 연 뒤 자세히보기를 누르면 요약 아래에 상세가 쌓이는 문제를 시뮬레이터에서 재현했다. 요약의 item 기반 이동을 제거하고 루트의 값 기반 경로로 통일했다. 수정 후 빌드 성공, 마커 → 요약 → 자세히보기 즉시 표시 → 뒤로가기 요약 → 지역 지도 복귀를 확인했다. 다른 오이의 목록 경로에서도 상세 → 요약 → 목록 복귀를 확인했고, 프로필 수집 목록 → 상세 → 프로필 복귀도 확인했다. 이 수정은 시뮬레이터에서 검증했으며 실제 iPhone에서는 추가 확인해야 한다.

## 카메라와 지도 복귀 수정 — 2026-10-26~27


실제 Jun iPhone에서 지도 → AR 카메라 진입 시 버튼과 ‘추적 정상’ 표시는 나오지만 카메라 영상은 검게 표시됐다. 같은 AR 카메라를 지도 없이 단독 실행하면 영상이 나왔고, 지도 렌더러를 해제한 뒤 진입해도 영상이 나오는 것을 사용자와 비교 확인했다.

`CampusExploreScene.suspendForARCamera()`는 AR 카메라 진입 때만 non-AR `ARView`를 앵커에서 분리하고 해제한다. 지도 엔티티·카메라 위치·마커·제스처 상태는 유지하고, 다시 표시할 때 새 렌더러에 연결한다. 홈과 프로필 메뉴의 카메라 진입 모두 이 경로를 사용한다. `RootTabView`의 카메라 활성 상태는 `fullScreenCover`의 `onDismiss`까지 유지해, 닫기 전환이 완료된 뒤 지도를 복원한다. 복원은 `HomeView.onAppear` 호출 여부에 의존하지 않는다.

일반 요약·상세 화면 이동과 앱 비활성화에서는 `setVisible`로 지도만 숨기고 같은 렌더러를 유지한다. 모든 화면 이탈에 렌더러 해제를 적용했을 때, 상세 복귀 후 핀치 값과 카메라 좌표는 바뀌지만 3D 지도는 갱신되지 않고 마커만 움직이는 회귀가 실제 iPhone에서 나타났다. 해제를 AR 진입으로 한정한 후 사용자가 상세 복귀·카메라 복귀 양쪽에서 건물과 마커가 함께 확대·축소되는 것을 확인했다. 진단용 카메라 좌표 로그는 제거했다.

검증: 기존 개인 서명 설정으로 iPhoneOS Debug 빌드·설치 성공. 사용자가 실제 iPhone에서 카메라 첫 진입 → 닫기 → 지도 표시·이동 → 카메라 재진입이 모두 정상임을 확인했다. 이 검증에서 사진·영상 저장, 경기장 합성, NFC는 다시 확인하지 않았다. 기존 AR 카메라 처리 코드와 서명 설정은 변경하지 않았고, 원인 비교용 임시 진입 코드는 제거했다.

2026-10-27 PR #93 브랜치에 최신 `develop`(`d8dd296`, #95 아이콘 포함)을 충돌 없이 병합한 뒤 generic iOS Simulator Debug 빌드(`CODE_SIGNING_ALLOWED=NO`), `run-campus-checks.sh`, `run-architecture-checks.sh`가 통과했다. 개인 서명·프로비저닝 설정과 별도 App Clip 원격 콘텐츠 변경은 포함하지 않았다.
