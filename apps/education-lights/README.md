저장소 루트에서 `cd apps/education-lights` 후 아래 명령을 실행한다. 이 PR은 소스 보관이며 기존 서비스 배포 경로를 변경하지 않는다.

## 실행

정적 웹 서버에서 `dist/`를 제공한다. Node 패키지와 외부 CDN, 빌드 단계가 없다.

```sh
python3 -m http.server 8777 --directory dist
```

## 경험

- 반투명 흰 구 96,000개로 만든 교육지구 건물. 제공된 기준 이미지의 곡면 외피·테라스·옥상 사다리꼴 매스를 해석한 개념 형상이며, 정밀 건축/BIM 모델이 아니다.
- 4방향 이미지에 맞춰 긴 수평 루버 외피, 열린 옥상 중정, 왼쪽 사다리꼴 홀, 비대칭 3단 테라스, 왼쪽 석재 기단·연결 통로, 오른쪽 계단식 원형 공간을 재배치했다. 정면·좌측·우측·뒷면 버튼과 기준 이미지 패널로 비교한다.
- 마우스 근처의 작은 웨이브, 클릭/탭 시 흩어짐과 재결합. 드래그 회전, 스크롤/핀치 확대, 키보드 조작.
- 파란 구는 기부 인증을 가정한 시연 상태. 모금률 슬라이더로 0–100% 전환.
- 자신의 메시지와 선택 사진 한 장을 흰 구로 저장하고, 인증 시연 버튼으로 파란 구로 전환. 이름/메시지 입력은 HTML로 해석하지 않는다.
- 예시 메시지 3종. 개인 메시지·사진은 이 브라우저의 localStorage에만 보관한다. 서버 전송·실제 기부 처리·공식 납입 인증은 없다.

## 성능 설계

- WebGL 1, GL_POINTS 구 스프라이트. GPU 정적 버퍼 합계 5,500,776바이트(약 5.25MiB). 점 96,000개 + 색을 그리지 않는 깊이 판별용 삼각형 35,466개.
- 건물이 모인 상태에서 점 표시 1회 + 깊이 처리 1회. 깊이 처리는 뒷면의 점이 앞면을 비쳐 지나가는 현상을 줄인다. 흩어진 상태에서는 깊이 처리를 생략한다.
- 323,883개 표면 후보에서 외벽·유리벽·지붕·테라스의 면 안쪽까지 배분한다. 별도 윤곽선은 전체 점의 약 0.6%로 제한하고, 아래층 유리벽에 20% 이상·테라스 포장에 12% 이상을 배분한다. 층마다 물러나는 벽 사이의 노출된 바닥과 왼쪽 기단 상부도 채운다.
- 표면의 실제 가로·세로 길이에 맞춰 행과 열 수를 배분하고, 행마다 반 칸씩 어긋나게 채운다. 연속된 표면을 보간해 격자에 뭉치거나 세로 줄처럼 빈틈이 생기는 현상을 줄인다. 4개의 교차 샘플 그룹으로 LOD를 구성한다.
- 기본 구 지름 계수를 7.0에서 4.9로 30% 줄였다. 모바일/가벼운 모드의 크기 보정은 최대 1.22배로 제한한다. 구별 하이라이트와 명암 대비를 낮춰 건물 표면이 더 부드럽게 이어지도록 했다. 파란 구를 더 크게 그리는 처리도 제거했다.
- 위치 웨이브·흩어짐·조명은 GPU 셰이더. 구마다 메시/재질/그림자/사진 텍스처를 만들지 않는다.
- 기본 96,000개. 터치 기기와 700px 이하 화면은 48,000개, 가벼운 모드는 24,000개 대표 샘플(동일한 전체 참여 범위와 비율). 개인 구가 대표 샘플 밖이면 그 구만 추가 렌더링 1회.
- 터치 기기 30fps 상한·DPR 최대 1.35; 가벼운 모드 30fps·DPR 1. PC DPR 최대 1.7.
- 화면 밖·숨겨진 탭에서 렌더링 중단, prefers-reduced-motion 대응, WebGL 컨텍스트 복원 처리.
- 사진은 긴 변 768px JPEG 0.8, 데이터 URL 최대 350,000자. 원본 사진은 보관하지 않는다.
- 추가 사진을 구마다 GPU에 올리지 않고 해당 이야기 패널을 열 때만 표시한다. 실서비스에서는 목록 페이지네이션·이미지 지연 로딩·썸네일 CDN을 추가해야 한다.

## 금액과 참여 인원

시연 목표 **9억6천만 원**, 최대 **96,000명**, **1인 1만 원**은 경험 확인용 가정이다. 공식 모금 목표나 확정된 최소 기부금이 아니다. 동일 금액 기부를 가정하므로 시연에서는 파란 구 비율과 금액 모금률이 일치한다.

실서비스에서는 한 사람당 구 하나와 고유 참여 ID를 유지하고, `verifiedAmount / targetAmount`와 `verifiedPeople / availableOrbs`를 각각 계산해야 한다. 금액이 다르면 두 비율을 같다고 표시하면 안 된다. 참여 인원이 구 수를 초과하면 구 수/밀도 또는 LOD 집계 정책을 결정해야 한다. 클라이언트 시연 버튼을 실제 인증 경로로 재사용하지 않는다.
