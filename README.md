# 오이기부 | BenchMark

**오이기부(오래 남는 이야기 기부)**는 작은 기부에 얽힌 이야기를 POSTECH 캠퍼스에 남기고, 다른 사람이 3D 지도와 현장 AR에서 발견할 수 있도록 만든 iOS 앱입니다. 벤치마크(BenchMark) 팀이 개발합니다.

- **캠퍼스 탐색:** 3D 지도에서 오이를 선택해 공개된 이야기를 읽고, 현장 AR에서 오이와 카드를 수집할 수 있습니다.
- **이야기 남기기:** 기부 증빙을 제출하면 AI 검사 결과를 확인할 수 있습니다. 제출 자료와 공개 요청은 앱 운영팀의 검토를 거칩니다. 이야기와 사진을 더하고 지도에서 위치를 정해 오이와 카드를 꾸밀 수 있습니다.
- **나만의 농장:** 수집한 카드를 다시 보고, 농부 캐릭터를 꾸밀 수 있습니다. 공개 이야기 탐색은 로그인 없이도 할 수 있습니다.

오이기부는 기부금을 직접 받거나 보관하지 않습니다. 실제 납입·취소·환불·기부금 영수증은 기부금을 받은 기관에 문의해 주세요. 앱의 AI 검사나 운영자 검토는 기관의 공식 납입 확인을 대신하지 않습니다.

| 처리하는 정보 | 사용하는 목적 |
| --- | --- |

기부 증빙에는 사용자가 첨부한 문자나 입금 정보가 들어 있을 수 있습니다. 증빙에 필요하지 않은 정보, 비밀번호와 인증번호는 제출하지 마세요. 제출한 증빙은 공개 이야기나 카드에 표시하지 않습니다. 승인된 공개 이야기에는 사용자가 공개를 위해 등록한 본문·사진과 위치가 표시됩니다.

- **외부 서비스:** 로그인에는 Apple·Google과 Supabase를, 서비스 데이터와 파일 보관에는 Supabase를 사용합니다. AI 검사 요청 시 검사 대상 자료를 OpenAI API에 전달해 분석 결과를 받습니다.
- **기기 권한:** 현재 위치와 카메라는 현장 수집과 AR에 사용합니다. 앱에서 이야기의 위치로 직접 선택한 좌표는 이야기와 함께 저장합니다. 위치·카메라 접근 권한은 iPhone 설정에서 변경할 수 있습니다.
- **보관과 삭제:** 앱의 **MY → 설정 → 회원 탈퇴**에서 본인 확인 후 연결된 로그인 계정과 앱에 저장된 본인 프로필, 이야기·사진, 증빙·검토 이력, 카드 기록과 설정을 삭제할 수 있습니다. 학교나 공식 수납처의 기록과 Apple·Google 계정 자체는 해당 기관 또는 서비스에서 관리합니다.

## iOS 실행 전 Supabase 설정

최신 코드를 받은 뒤 기존 `52gibu` 프로젝트에 접근 가능한 Supabase CLI 인증으로 한 번 실행합니다.

```sh
python3 scripts/configure-ios-service.py --from-cli --http-check
```

본 앱과 App Clip의 Git 제외 `Service.local.plist`를 생성하고 실제 공개 API 연결을 검사합니다. 이후 Xcode에서 `OiDonation`을 빌드합니다. 두 타깃은 빌드 시작 시 각 설정을 검증하며, 누락되거나 잘못된 설정이면 준비 명령을 안내하고 중단합니다. 빌드 중에는 키 조회나 서버 호출을 하지 않습니다.

CI에서는 기존 프로젝트의 공개 클라이언트 키를 `OI_SUPABASE_PUBLISHABLE_KEY` 환경변수로 주입하고 `python3 scripts/configure-ios-service.py`를 빌드 전에 실행합니다. 키 값·프로파일·개인 서명 설정은 커밋하지 않습니다. 자세한 내용은 [Supabase 연동 문서](docs/supabase-flow.md#로컬-실행-설정)를 참고합니다.

# 깃 전략

### 태그 컨벤션

`init` : 가장 처음 Initial Commit에 태그 붙이기

`feat` : 새로운 기능 구현 시 사용

`fix` : 버그나 오류 해결 시 사용

`docs` : README, 템플릿 등 프로젝트 내 문서 수정 시 사용

`setting` : 프로젝트 관련 설정 변경 시 사용

`add` : 사진 등 에셋이나 라이브러리 추가 시 사용

`refactor` : 기존 코드를 리팩토링하거나 수정할 시 사용

`chore` : 별로 중요한 수정이 아닐 시 사용

### 커밋 컨벤션

태그는 반드시 **소문자**로 작성합니다.

내용은 한글로 작성합니다.

제목이 **50자**를 넘지 않도록, 간단하게 명령조로 작성합니다. 설명이 필요한 경우 description에 작성합니다.

```markdown
[feat] 로그인 기능 구현
```

### 브랜치 컨벤션

태그/#이슈번호-작업하는 파일

```markdown
feat/#1-loginUI
```

### 브랜치 전략

`main` : 출시(release)에 사용하는 브랜치입니다.

`develop` : 개발된 기능들을 최종적으로 합쳐서 확인하는 브랜치입니다.

- 기본 브랜치이며 개발을 마친 후에 반드시 develop에 머지합니다.
- 개인 브랜치에서 작업을 마치면, 개인 브랜치에서 develop 브랜치를 머지한 후에 develop에 pull request를 요청합니다.

`feature` : 태그를 붙이는 모든 브랜치들을 말합니다. 기능 개발, 버그 수정 등을 반드시 이 브랜치에서 진행해주세요.
