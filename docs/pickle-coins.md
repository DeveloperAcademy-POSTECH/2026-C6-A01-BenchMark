## 구현과 적용 상태

`20261118113207_oi_pickle_coins.sql`은 지갑·원장·기존 자료 처리·소유권·AI 계약·capability를 하나의 트랜잭션으로 적용한다. 승인된 과거 증빙의 중복 확인용 지문이 없거나 기존 함수가 확인한 버전과 다르면 적용을 중단한다. 실패한 migration이 코인 비용만 먼저 활성화하지 않는다.

| API | 역할 |
| --- | --- |
| `oi_pickle_wallet()` / `oi_farmer_inventory()` | 본인 잔액·무제한 여부·소유 의상 조회 |
| `oi_purchase_farmer_item(p_item,p_operation)` | 3개 차감과 영구 소유권·같은 작업 재시도 |
| `oi_start_coin_evidence` / `oi_submit_coin_evidence` | 계정별 비공개 업로드와 별도 AI 동의 |
| `oi_cancel_coin_evidence(p_id)` | 중단된 자료 취소와 이미 확정된 지급 결과 보존 |
| `analyze-donation-evidence` | 인증된 세션·소유권·동의·제출 버전을 재검증해 AI 확인 |
| `oi_prepare_coin_evidence` / `oi_coin_evidence_review` | 서비스 전용 처리 잠금과 원자적 중복 검사·지급 |

지급·차감은 서버가 금액을 결정한다. 앱은 `coin_reward`와 `wallet` 영수증을 확인하며, 실패한 잔액 조회로 기존 콘텐츠나 마지막 확인 잔액을 지우지 않는다. 구매 응답 유실은 소유 목록으로 재확인하고, 중단된 증서 업로드는 같은 요청 ID·파일로 재개한다. 계정 통합 시 자료와 원장을 보존한다. 정상 자료로 바꿔야 하는 영구 분석 실패는 명시적 취소 결과를 확인한 뒤 새 자료를 첨부한다.

자동 승인에는 기부자명·기부일·양수 금액·통화가 보여야 한다. 최소 기부금 기준은 없다. 같은 파일·증서번호 또는 번호를 가린 사본의 복합정보를 서버 전용 HMAC으로 비교한다. 같은 메타정보라도 서로 다른 증서번호가 확인되면 별도 증서로 처리한다. AI는 발급기관의 문서 진위나 제출자 본인 여부를 보증하지 않는다. 지문과 보상 기록은 계정 탈퇴 시 삭제하므로 탈퇴 후 재가입까지 영구적으로 중복을 차단하는 정책은 아니다.

코드 구현과 [DB·Edge·iOS 검증 및 최종 화면](verification/pickle-coins-506/README.md)을 완료했다. 2026-11-18 운영 52gibu에 `20261118113207_oi_pickle_coins`를 적용했고 기존 계정 13개의 가입 보상, 기존 공개 오이 1개의 무료 유지, 과거 수집 10건의 무보상 표시를 확인했다. 지정된 로그인 3계정의 서버 무제한 설정도 실제 조회로 모두 확인했다. 익명의 지갑·검수 RPC 실행 권한은 없고 보안 Advisor 신규 항목은 없었다.

2026-11-18 사용자가 OpenAI API 전송과 운영 배포를 명시적으로 승인한 뒤 `analyze-donation-evidence` v8을 배포했다. 상태 ACTIVE·JWT 검증 true와 배포 파일 네 개의 소스 일치를 확인했다. 앱 사용자의 자료별 동의·계정·제출본을 검증한 경우에만 선택한 자료를 OpenAI Responses API로 전송한다. 실제 HTTP에서 익명 지갑은 401, 인증 함수는 403을 반환했고 검수·지급 RPC는 서비스 역할에만 실행 권한이 있다. 실제 증서의 AI 결과와 앱 배포·실기기 설치는 검증 범위에 포함하지 않는다. 테스트용 가상 자료와 실제 사용자 자료를 섞지 않는다.

AI 인증에는 POSTECH의 기부 증서·기부금 영수증만 제출한다. 다른 기관의 자료·문자·입금내역·단순 약정서는 대상이 아니다. 과거 수집 기록은 보상 대상에서 제외한다.
