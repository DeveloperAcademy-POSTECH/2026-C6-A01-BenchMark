# 카드 양면 저장·공유 — #308

2026-11-13 사용자 확정 범위: 본 앱에서 꾸민 앞·뒷면 이미지 저장/공유, 동일 버전 서버 제출, 승인된 양면을 App Clip에서 표시한다.

## 저장 계약

기존 비공개 `oi-story-media` 버킷과 `oi_stories.card_snapshot_id`를 사용한다. 새 `card_snapshot_format`은 기본 1(기존 단면), 신규 양면은 2다. 영구 URL이나 만료되는 서명 URL을 DB에 저장하지 않는다.

| 파일 | 경로 (`owner/story` 접두사 생략) | 픽셀 |
| --- | --- | --- |
| 앞면 원본 | `card/snapshot.png` | 신규 렌더 1086×1506 |
| 뒷면 원본 | `card/snapshot/back.png` | 1086×1506 |
| 앞면 미리보기 | `card/snapshot/front-preview.png` | 724×1004 |
| 뒷면 미리보기 | `card/snapshot/back-preview.png` | 724×1004 |

앞면 경로는 구버전 앱의 공개 카드 조회와 호환된다. 기존 PNG를 재사용하면 원래 해상도를 보존한다. 각 파일은 PNG·8MiB 이하이며 기존 디코더가 허용하는 최대 2048px 안에서 생성한다. 버전 UUID는 네 파일의 해시를 모두 포함하므로 뒷면만 바뀌어도 새 경로를 쓴다. 업로드는 덮어쓰지 않으며 응답 유실/재시도는 기존 바이트와 일치할 때만 재사용한다.

## 제출·검토·조회

1. 카드 렌더러는 버튼·편집 UI 없이 동일한 362×502 좌표계로 출력한다. 뒷면은 스크롤 위치를 캡처하지 않고 전체 본문이 들어가는 글자 크기를 계산한다. 들어가지 않으면 저장/제출을 명확히 거절한다.
2. 본 앱은 네 파일 업로드가 모두 성공한 뒤 `submit_story`에 버전 ID와 형식 2를 넘긴다. 중간 실패 시 서버 초안과 현재 카드 참조를 유지한다. 아직 연결되지 않은 부분 업로드는 비공개로 남으며 다시 요청할 때 재사용한다. 자동 청소 정책은 추가하지 않는다.
3. DB는 PNG MIME·크기·네 경로 존재를 검사하고 이야기의 리비전과 함께 연결한다. 운영자는 앞·뒷면과 두 미리보기를 모두 불러와 확인한 뒤 승인한다. 승인 RPC는 같은 카드 ID와 형식 2를 요구한다. 미리보기와 원본 내용의 일치는 운영자 확인 대상이다.
4. 익명/App Clip은 `published` 상태의 현재 버전만 조회·서명 URL 발급이 가능하다. 작성자와 운영자의 비공개 조회는 기존 권한을 유지한다. 다른 작성자의 초안 및 미참조 파일은 공개하지 않는다.
5. App Clip은 현재 면의 미리보기만 실제 다운로드한다. 탭 또는 접근성 동작으로 뒤집는다. 실패 후 다시 불러오기는 공개 상태를 재조회하여 새 서명 URL을 받는다. 구형 단면 카드는 앞면만 표시한다.
6. 공개 해제는 새 읽기/URL 발급을 차단한다. 이미 발급한 URL은 기존 유효기간(300초)까지 동작할 수 있고 기기에 이미 저장한 이미지 사본을 원격 삭제하지는 않는다.

저장된 카드 앞면을 재사용해 이야기를 수정하는 경우에도 검토 화면은 현재 본문으로 뒷면을 새로 렌더링한다. 공개 지도에서는 형식 2의 저장된 뒷면을 표시한다. 형식 1의 과거 지도 엽서는 기존 본문 표시 방식을 유지한다.

## 본 앱 저장·공유

- 카드 꾸미기의 `카드 이미지 저장·공유`, 공개 검토 화면의 같은 버튼, 본인이 작성한 지도 카드의 같은 버튼에서 연다.
- `앞면`, `뒷면`, `앞·뒷면 모두`를 선택하고 미리보기를 확인한다. 과거 저장 카드에 뒷면이 없으면 앞면만 제공한다.
- 사진첩 저장은 기존 `ARPhotoLibraryService`의 추가 전용 권한을 사용한다. 두 장은 투명 테두리를 보존하는 PNG 리소스로 한 PhotoKit 변경 작업에 저장한다. 기존 AR 단일 사진 저장 경로는 유지한다. 거절/실패 시 재시도할 수 있도록 이미지를 유지한다.
- 공유는 이미지 배열을 iOS 기본 공유창에 넘긴다. 인스타그램 자동 게시나 특정 앱 표시를 보장하지 않는다. 사용자가 사진첩에서 이미지를 선택해 게시할 수도 있다.
- 오이 스냅샷 준비가 끝나기 전에는 저장을 열지 않는다. 공개 승인 전에도 작성자가 자신의 이미지를 개인 저장할 수 있다.

## 서버 적용 상태와 순서

**현재 상태: 2026-11-13 운영 52gibu에 적용 완료.** 자동 승인 검토에서 최초 적용이 보류된 뒤 사용자가 PR #311의 운영 DB 적용을 명시적으로 승인했다. 해당 마이그레이션과 배포 이력(`20261113070000`)만 한 트랜잭션으로 적용했다. 새 열·읽기 정책·기능 표시와 비공개 버킷을 확인했고, 운영 DB에서도 가상 자료를 사용하는 권한·승인 검사를 실행한 뒤 전부 rollback했다. 키나 개인 계정 자료는 변경하지 않았다.

1. 이 PR의 `20261113070000_oi_duplex_story_card.sql`을 검토한다. 기존 단면 데이터를 기본 형식 1로 보존하는 추가 마이그레이션이다.
2. 명시적 운영 DB 적용 승인 후 해당 마이그레이션만 적용하고 배포 이력을 기록한다. 검토 전 다른 미적용 마이그레이션을 한꺼번에 push하지 않는다. 변경 지점이 예상과 다르면 전체 트랜잭션을 중단한다.
3. 최신 운영자 앱으로 양면 검토를 준비하고 본 앱·App Clip을 배포한다. 구형 운영자 앱은 형식 2를 승인할 수 없다.
4. API의 `duplex_story_card` 기능 표시와 가상 계정의 업로드 → 운영자 검토 → 비로그인 App Clip 조회를 확인한다.

서버 기능 표시가 없으면 신규 양면 공개 요청을 안내와 함께 막고 기기 초안·사진 저장은 유지한다. 기존 단면 조회와 공개 검토는 유지한다. 카드 원본 사진과 편집 자료의 기기 간 동기화는 이번 범위가 아니다.

## 검증

- 격리된 PostgreSQL에서 전체 마이그레이션 및 기존 회귀 검사 통과. 신규 `oi-duplex-story-card.sql`은 부분 업로드의 원자적 실패, 타인/익명 비공개 차단, 운영자 전체 파일 조회, 구형 운영자 승인 차단, 승인 버전만 공개, 숨김 후 접근 차단을 확인한다. 기존 단면 카드 검사도 새 스키마에서 다시 통과했다. 모든 가상 자료는 rollback한다.
- iOS 27.2 `OiFlowChecks`: 90개 실행, 87개 통과, 3개 명시적 조작 테스트 skip, 실패 0. 양면 버전 해시·원본/미리보기 크기·투명 테두리·장문 처리·부분 업로드 재시도·구형 서버 차단과 기존 공개/초안 호환을 포함한다.
- 후속 UI 캡처 및 업로드 검사 3개 통과: 사진첩 저장/공유 면 선택 화면과 App Clip 앞면 캡처를 직접 확인했다.
- 최종 렌더·캡처 검사 2개 통과. iPhone용 본 앱·App Clip 서명 빌드와 앱 서명 검증도 통과했다.
- `run-app-clip-checks.sh`: 링크·공개 목록·재조회·수집 취소 검사. 기존 Swift 동시성 경고는 남아 있다.

- 운영 검사 후 가상 사용자·파일 메타데이터 0건을 확인했다. 익명 HTTPS API에서 새 카드 형식 열의 조회(이야기 내용 없이 `limit=0`)도 통과했다.
