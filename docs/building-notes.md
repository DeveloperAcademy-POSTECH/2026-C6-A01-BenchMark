# 지도 건물 쪽지 — #401

2026-11-16 사용자 요청과 즉시 공개·신고 후 검토 결정에 따른 구현이다. develop `2d1e583`에서 시작해 `c19003b`까지 통합했다. 이슈 브랜치는 `feat/#401-building-notes`다. **2026-11-16 운영 52gibu에 두 마이그레이션과 적용 이력을 함께 등록**했고, 저장된 SQL이 저장소 원문과 일치함을 확인했다.

## 화면과 동작

- [Figma 쪽지 뷰](https://www.figma.com/design/nEDJaJBFrdzBCa1WcgADHH?node-id=5917-11195)의 흰 패널, 상단 40pt 모서리, Paperlogy, 회색/연두색 말풍선, 둥근 입력란을 사용한다. 지도는 실제 RealityKit 화면이며 Figma 지도를 이미지로 덮지 않는다.
- 메인 지도의 건물 또는 건물 이름을 선택하면 확대한다. 선택 화면에서는 원형·각진 구역 수 표시와 오이 오버레이를 숨긴다. 뒤로 가면 진입 전 카메라 위치·확대율·방향과 구역 상태를 복원한다.
- 건물 외곽 다각형과 높이의 ray intersection으로 가장 가까운 건물을 선택한다. 철거된 포스빌6을 제외하고 이름·높이가 있는 89개 건물을 지원한다. 교육지구의 기존 별도 안내 동작은 유지한다.
- 로그인 없이 공개 글을 읽고, 등록·신고는 로그인해야 한다. 작성자 표시는 공개 학번·학과, 정보가 없으면 공개 닉네임이다. 비공개 학교 자료 요약과 이메일은 읽지 않는다.
- 각 쪽지 옆의 `더보기(…)`를 눌러 본인 글은 삭제, 다른 사람 글은 신고·작성자 차단을 실행한다. 더보기의 터치 영역은 44×44pt이며, 본인 삭제는 확인창을 거친다. 글을 길게 눌러도 같은 메뉴를 열 수 있다. 신고 내용은 공개하지 않는다. 신고를 저장하면 운영자 수동 검토를 기다린다. 운영자 메뉴의 `건물 글 신고`에서 본문과 미처리 신고를 확인하고 유지/삭제 사유를 남긴다. 앱은 AI 함수를 자동 호출하지 않는다.
- 긴 목록은 최근 50개부터 읽고 이전 글을 더 불러온다. 최신 페이지를 읽는 동안 전경에서 30초마다 갱신하며, 작성 중·이전 글 열람 중·백그라운드에서는 자동 갱신을 멈춘다.

## 저장·권한 계약

마이그레이션: `supabase/migrations/20261116090000_oi_building_notes.sql`, `supabase/migrations/20261116090100_oi_building_note_moderation.sql`.

| RPC | 권한 / 역할 |
| --- | --- |
| `oi_building_notes` | 익명/로그인: 건물별 공개 글, timestamp+UUID cursor, 최대 50개 |
| `oi_post_building_note` | 로그인: 서버에서 작성자 결정, 동일 UUID·본문 재전송은 같은 글 반환 |
| `oi_delete_building_note` | 작성자: 본인 글 삭제, 병합된 계정의 이전 작성물 포함 |
| `oi_report_building_note` | 로그인: 다른 글 비공개 신고, 같은 계정의 중복 신고 방지 |
| `oi_building_note_reports` | 운영자: 신고함, 50개씩 조회 |
| `oi_review_building_note` | 운영자: 신고 종결/글 삭제, 사유와 감사 기록 |
| `oi_moderate_building_note` | service_role 전용: 세션·신고 소유권 확인, AI 작업 확보, 서버 판정 적용 |

세 테이블은 `benchmark_private`에 두고 RLS를 활성화하며 클라이언트의 직접 읽기·쓰기를 허용하지 않는다. RPC는 비어 있는 search_path와 명시적인 실행 권한을 사용한다. 글·신고의 소유권은 `oi_account_members`를 통해 canonical 계정을 따른다. 탈퇴 처리 중·콘텐츠 제한 계정의 글은 공개 조회에서 제외되고, 계정 member 삭제 시 글·연관 신고도 제거된다.

기술 기본값: 글 140 Unicode scalar, 계정별 5초 간격/24시간 50건, 신고 24시간 20건, 신고 설명·검토 사유 1,000자. 클라이언트는 한글 NFC 정규화 후 길이를 검사한다. 기부·학교 확인과 무관한 도배 방지 설정이며, 운영 수치 변경 시 서버와 앱의 표시를 함께 갱신한다.

등록 성공 응답의 글 ID·작성자·건물·본문을 확인한 뒤 입력을 지운다. 응답을 잃으면 같은 UUID로 재전송하고, 화면 종료·로그아웃·계정 전환 뒤 도착한 응답은 적용하지 않는다. 읽기 시작 후 작성/삭제가 완료된 경우 이전 목록 응답으로 되돌리지 않는다.

## 수동 검토 운영과 준비된 AI 함수

2026-11-16 사용자는 운영자 수동 검토로 시작하기로 결정했다. 준비된 moderate-building-note 함수는 OI_BUILDING_NOTE_AI_ENABLED=false로 배포한다. 쪽지 작성·조회·삭제·신고와 운영자의 수동 처리는 AI와 독립적으로 동작한다. 향후 AI 활성화는 별도 결정한다.

준비된 AI 함수는 도니의 `origin/feat/#388-ai-story-moderation`에서 이야기 **공개 전** 검수 함수 `moderate-story`를 확인했다. 이 기능과 건물 글의 **신고 후** 검수 계약은 다르므로, 이야기/배치 흐름을 합치지 않고 해당 브랜치의 `requestStructuredAnalysis` 공통 호출부만 동일하게 반영했다. 새 `moderate-building-note`는 같은 서버 `OPENAI_API_KEY`와 `OPENAI_STORY_MODERATION_MODEL` 설정을 사용한다. 키를 앱이나 저장소에 추가하지 않는다.

향후 AI 활성화 시 별도 호출자는 저장된 신고 ID만 전송하도록 설계했다. 현재 앱은 신고 접수만 한다. 함수는 실제 로그인 토큰과 세션을 검증하고, DB에서 확보한 본문만 OpenAI에 보낸다. 공개 프로필, 신고자 정보, 비공개 신고 설명은 전달하지 않는다. 모든 글을 신뢰하지 않는 입력으로 다루며 링크나 지시를 실행하지 않는다. 욕설·괴롭힘·개인정보·명확한 권리 침해·선정성·폭력·스팸·명시적인 사기만 삭제 사유로 받으며, 일상적인 불만·비판·줄임말은 허용한다. 판단이 모호하면 운영자에게 넘긴다. 출력은 정해진 판정/사유 코드만 허용한다.

AI가 확인하는 동안 본문 해시와 90초 작업 lease를 유지하고, 최종 적용 전에 세션·신고 상태를 다시 확인한다. 신고당 최대 3번 시도하며 이미 처리한 신고는 다시 AI를 호출하지 않는다. 운영자가 먼저 처리한 결과는 늦은 AI 응답으로 변경하지 않는다. 신고 접수 후 네트워크 끊김·함수 미배포·AI 오류가 나도 신고는 운영자 큐에 남고 앱은 신고 실패로 표시하지 않는다. 감사 기록은 `building_note_ai:*`로 수동 조치와 구별한다.

운영 적용 순서:

1. 기존 마이그레이션 이력과 대조한 뒤 두 SQL을 순서대로 적용한다.
2. `moderate-building-note` Edge Function을 배포한다. 기존 서버 비밀키 설정을 사용하며 OI_BUILDING_NOTE_AI_ENABLED=false를 유지한다. 신고함과 운영자 수동 검토를 사용한다.
3. 가상 글로 공개 읽기, 작성·본인 삭제, 다른 계정 신고와 운영자 수동 처리를 확인한다. AI의 자동 삭제·유지는 이번 운영 검증에서 실행하지 않는다.

2026-11-16 적용 결과: 운영 52gibu에 `20261116090000`·`20261116090100`과 건물 89곳을 등록했다. `moderate-building-note`를 배포하고 `OI_BUILDING_NOTE_AI_ENABLED=false`를 설정했다. 공개 RPC의 익명 조회 200, 익명 등록 거부 401, Edge Function의 미인증 거부 401을 확인했다. 실제 OpenAI 호출과 자동 판정은 실행하지 않았다. SQL 미배포 환경에서는 기능 미제공 안내와 재시도를 표시하고 등록 성공으로 오인시키지 않는다.
