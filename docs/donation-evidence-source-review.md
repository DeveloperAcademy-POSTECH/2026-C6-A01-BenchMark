## 확보하지 못한 자료

2026-11-05 공개 검색에서 POSTECH 입금 확인 문자의 원본·발신 정보·실제 납입을 독립적으로 대조할 수 있는 타 기부자의 수신 후기를 확보하지 못했다. 검색어는 ‘포스텍 기부 입금 확인 문자 후기’, ‘포항공대 기부 후기’, ‘포스텍 기부금 정상적으로 문자’와 공식 기부 사이트를 사용했다. 검색되지 않았다는 사실은 그러한 후기가 존재하지 않는다는 뜻이 아니다.

사용자가 제공한 문자 사진은 제품 요구사항을 이해하는 예시다. 학교나 운영자가 확인을 마친 정상 표본으로 소급 등록하지 않으며, 원본·개인정보·사용자 파일 경로를 저장소에 복사하지 않는다. 팀의 검토 완료 사례 저장소도 이번 조사에서 확보하지 않았다. 구현과 결과에 ‘기존 기부자 사례와 일치’라는 근거를 만들지 않는다.

향후 동의와 운영자 검토를 거친 정상 자료가 쌓이면 검토 근거·자료 버전·검토 시점이 있는 별도 참조 집합으로 편입해야 한다. 단순히 문구가 비슷하거나 공개 후기가 여러 개라는 이유로 자동 충족시키지 않는다. 기관 공통 문구는 여러 정상 기부자에게 반복될 수 있으므로 같은 문구 자체를 중복 거래 지문으로 삼지 않는다.

## 평가 자료의 성격

[`donation-evidence-cases.json`](../supabase/tests/fixtures/donation-evidence-cases.json)은 **가상 평가 시나리오**다. 모든 본문·거래 참조는 테스트용으로 작성했으며 실제 기부자의 문자, 학교가 확인한 발신 양식, 검토 완료 기부 이력이 아니다. 공식 문의 번호와 기관명만 공개 공식 정보로 사용한다.

평가에서는 ‘증빙 충족’, ‘추가 자료 필요’, ‘수동 확인’, ‘조작 의심’, ‘중복 증빙’, ‘기부와 무관’을 구분한다. 충족은 앱의 근거 충분성 판단이며 원본 진위·은행 납입의 확정이나 글 작성 권한 자동 부여가 아니다. 판정 기준 테스트와 실제 모델의 이미지/문서 추출 정확도 평가는 별도로 집계해야 한다.

필수 비교쌍은 다음과 같다.

- 약정 접수만 있는 문자 / 이후 명시적인 입금 완료 문자가 있는 이력
- 실제 발신 번호 일치 / 본문에만 공식 번호가 있는 문자 / 연락처 이름만 있는 문자
- 정상적인 개인정보 가림 / 구체적인 편집 흔적·문서 내부 모순
- 입금 완료 / 이후 취소·환불 / 기부와 무관한 다른 납부
- 다른 신청에서 같은 바이트 또는 고유 거래 참조 재사용 / 같은 신청의 정상 재시도
- 다른 기부자에게 발송된 같은 공통 문구 / 동일 거래의 재사용
