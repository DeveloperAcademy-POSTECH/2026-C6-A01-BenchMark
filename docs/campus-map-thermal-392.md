# 메인 지도 대기 발열과 이야기 표시 · #392

2026-11-16 사용자 확정 범위를 기존 `fix/#392-campus-map-thermal` 브랜치에서 구현했다. 원격 브랜치를 pull하고 최신 develop `856e8de`(#398)을 통합했다. 기존 브랜치의 유휴 화면 유지와 교육지구 근거리 지연 준비를 보존한다.

## 동작과 구현

- 평상시 개요에서는 공개·본인 오이의 좌표와 구역별 숫자만 유지한다. 캐릭터 버튼·사진 다운로드·3D 모델 준비는 시작하지 않는다. 숫자 패널은 기존 클러스터 경계를 따라 단계적으로 확대하며, 마지막 구역을 선택하면 이야기 목록과 주변 오이를 표시한다. 마지막 구역의 카메라 이동도 현재 방향을 유지하며 애니메이션한다.
- 목록을 닫으면 오이를 제거하고 현재 지도 위치·확대율을 유지한다. 이야기 검색 결과와 목록의 기존 정렬·드래그·닫기, 작성/배치 미리보기·요약·현장 AR은 유지한다.
- 공개 모델은 기존 직렬 로딩과 최대 8개 원본 캐시를 유지한다. 본인 모델도 단일 Task로 공유하고 최대 8개 원본을 보관한다. 화면 밖 인스턴스는 제거하고, 목록 닫기·계정/외형 변경·가림 화면 전환 뒤 완료한 준비 결과는 표시하지 않는다. 실제로 표시 중인 복제본은 캐시 축출 때문에 다시 준비하지 않는다. 본인 모델 준비 후에는 현재 화면의 대상을 다시 확인해 로딩 중 새로 보인 오이도 준비한다. 실패한 파일은 같은 작업 안에서 반복 재시도하지 않는다.
- 홈 지도는 움직임이 끝난 뒤 2초 후 마지막 RealityKit 프레임을 표시하고 같은 ARView를 뷰 계층에서 분리한다. 터치·카메라 이동·뷰포트·데이터 변경 시 기존 렌더러와 카메라로 복귀한다. 다른 화면이 덮을 때는 렌더러와 인스턴스를 해제한다. 원본 메시·캐릭터 텍스처·해상도·색상과 화면 밝기를 낮추지 않는다.
- 교육지구 far 메시만 첫 준비에 포함하고 near 메시를 실제 가까이 볼 때 준비한다. 건물 선택은 현재 카메라 투영의 광선과 하나의 로컬 경계 상자만 검사한다. 많은 진주 삼각형의 충돌 메시를 만들지 않으며 정지 화면의 첫 터치도 처리한다. 기존 글자 버튼과 같은 안내를 연다.
- 안내의 소개·본문·조감도·배치도를 하나의 기본 버튼으로 묶어 기존 ‘빛으로 지은 이야기 체험’과 같은 상태·목적지를 사용한다. 공식 사업 링크는 별도 동작을 유지한다.

## 실기기 검증 조건

Jun iPhone(iPhone 17, iOS 26.7.3), Release, 같은 계정·지도 데이터와 화면 밝기 100%·USB 충전 상태에서 측정했다. 변경 전은 최신 develop의 별도 소스 사본으로 빌드했다. 수정 후는 이슈 브랜치에서 빌드했다. 사용자에게 지도 무조작 유지를 요청했고 테스트 중 앱·시스템 밝기를 변경하지 않았다.

최초 실행은 진단 빌드에서 `Library/Caches/CampusGeometry-v1`만 비운 뒤 측정하고, 재실행은 캐시를 보존했다. 초안·사진·계정·기기 배치를 삭제하지 않았다. 지도 준비 시간은 `CampusExploreScene.load()`의 시작부터 ready까지이며 앱 전체 실행 시간이나 통계적 p95가 아니다.

진단 표식 없는 빌드 또는 Instruments 연결에 실패한 기록은 수치 비교에서 제외했다. 설치 경로가 바뀐 원인을 다른 작업이라고 단정하지 않는다. 이후 앱 경로·진단 표식·프로세스를 대조했고, 수정 후에는 Instruments 직접 실행 방식으로 유효한 기록을 확보했다. 진단용 캐시 초기화·이미지 저장·로그·자동 잠금 방지 코드는 최종 앱 소스에서 제거했다.

CPU는 Instruments가 보고한 수치다. GPU 제출 수는 FPS가 아니며 전체 앱의 소비 전력이 0이라는 뜻도 아니다. Power Profiler의 영향 지표는 도구의 원시 점수이고 Watt·Joule로 해석하지 않는다. 화면 전력은 남아 있으며, 충전 중 시스템 배터리 소모 `%/h`가 0으로 보고되어 절대 전력·배터리 지속 시간 개선률은 계산하지 않았다.

수정 후 Power Profiler의 `Foreground - Active` 구간(약 7.11~36.78초)과 GPU/CPU 분석 구간이 겹치는 것을 확인했다. 앱이 백그라운드에 들어간 결과를 정지 지도 성능으로 계산하지 않았다. 실제 정지 PNG(1206×2622px)의 네 모서리는 알파 0이며 투명 픽셀 966,264개를 확인해 검정 배경으로 바뀌지 않는 것도 검사했다.

측정 전 기기는 Serious 열 상태였다. 수정 후 최초 실행도 Serious에서 시작했고 후속 전력 측정은 Nominal이었다. 측정 사이 재설치·재실행·종료와 경과 시간이 있으므로 온도 변화 전체를 코드 효과로 단정하지 않는다. 장시간 캠퍼스 탐색·배터리 사용 시간은 별도 실사용 관찰이 필요하다.

## 회귀 검사와 재현

`OiFlowChecks`의 지도 검사 전체, 교육지구 LOD·오프라인 체험 진입, 실제 홈 캡처 등 **24개 검사 통과**. 목록을 열기 전 오이 준비 없음·목록에서만 표시·닫을 때 제거, 공개/본인 오이 구분·회전/발 위치·계정 제거, 핀치/팬/범위 복원·숫자 패널 투명도·가림 화면 복귀·정지 프레임 후 동일 렌더러 복귀·교육지구 첫 터치를 확인한다. 실제 원격 이야기나 기부·카드 요청을 쓰지 않았다.

PR 전 리뷰에서 ‘다른 모델 준비 중 확대율이 바뀌어 앞서 건너뛴 오이가 보이게 되는 경우’를 재현했다. 수정 전에는 그 오이의 요청과 엔티티가 없어 테스트가 실패했고, 현재 화면 재확인 방식으로 고친 뒤 동일 테스트와 전체 24개가 통과했다. 이 보완은 모델 로딩 중인 목록 화면에만 영향을 주며, 위의 정지 개요 성능 측정에는 캐릭터 준비가 없다.

진단 플래그 없는 최종 Release 빌드도 성공했으며 같은 iPhone에 설치·실행했다. 기존 앱 데이터는 보존했다. Swift 소스의 진단 코드 제거와 `git diff --check`를 확인했다.

- CPU/메모리: `xcrun xctrace record --template 'Activity Monitor' ... --time-limit 30s`
- GPU: `Metal System Trace`의 `metal-application-command-buffer-submissions`
- 전력/전면 상태: `Power Profiler`의 `ProcessCPUUsage`, `ProcessSubsystemPowerImpact`, `DisplayBrightnessLevel`, `DeviceChargingState`, `device-thermal-state-intervals`, `life-cycle-period`
- 이 환경에서 일부 `--attach <PID>` 검색이 실패해 앱 이름 또는 `--launch -- com.Spero.OiDonation`으로 기록했다. 기록 종료·저장 완료 후에 export해야 한다.
- 원본 `.trace`와 서명 설정은 저장소에 포함하지 않는다. 원본에는 다른 프로세스·기기 정보가 들어갈 수 있어 팀 공유 문서에는 집계와 조건만 기록한다.
