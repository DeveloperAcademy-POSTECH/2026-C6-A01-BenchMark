# 화면 이탈 후 AR·카메라·3D 실행 점검 — #417

2026-11-17 사용자 요청에 따라 최신 develop 기반에서 화면 진입·종료, 앱 비활성화, 비동기 권한·모델 로딩, 결과 시트 표시 경로를 점검했다. 기존 #413 구슬 복귀 배경 동기화 수정은 보존했다.

## 확인한 원인과 수정

- **교육지구 WebGL:** `EducationLightExperience`는 scenePhase만 추적했고 화면 이탈·WKWebView 해제 시 중단 호출이 없었다. 화면 표시 여부와 앱 활성 상태를 함께 확인하고, 닫기·이탈·UIView 해제 시 중단한다. JS 중단 플래그를 즉시 설정해 초기화 중에도 상태를 전달하고, 늦은 ready 응답은 저장된 비활성 상태를 유지한다. 숨긴 화면의 계정 갱신 이벤트도 보내지 않는다. 다시 표시되고 앱이 활성일 때만 재개한다.
- **AR 촬영 결과:** 사진·영상 결과 시트는 카메라 화면의 onDisappear를 발생시키지 않아 뒤의 세션이 계속 실행될 수 있었다. 결과가 하나라도 표시되면 시작 작업·카운트다운을 취소하고 AR·위치 추적을 중단한다. 앱 복귀·녹화 종료·재시도 콜백이 결과창 뒤에서 세션을 재개하지 못하게 한다. 모든 결과가 닫힌 뒤 화면이 보이고 활성인 경우에만 재개한다. 실제 UIView 해제에도 세션 종료를 연결했다.
- AR 세션을 일시 정지할 때 캐릭터 동작 재생도 중단한다. 다시 시작할 때 사용자가 재생 중이던 동작만 재개하고, 사용자가 직접 일시 정지한 동작은 그대로 둔다.
- **실기기 후속 확인:** ARSession.pause 이후에도 화면에 붙어 있는 ARView가 Metal 작업을 계속 제출했다. `ARCameraView`를 UIView 컨테이너로 감싸 준비 상태가 아니면 렌더러를 화면에서 분리한다. 재개 시 동일한 ARView·장면을 다시 붙여 선택한 모델과 배치를 보존한다. 세션·장면을 새로 생성하지 않는다.

## 검증과 한계

- `sh apps/ios/Tests/run-ar-recovery-checks.sh`: 권한 요청 경합·세션 중단/복구 검사 통과.

- iOS 시뮬레이터 회귀 검사 4개 통과(`Oi417CompletedLifecycle.xcresult`). 실제 WebKit에서 화면을 숨긴 동안 구슬 진행률이 고정되고, 늦은 ready에도 중단을 유지하며, 재표시/활성 전환 후 재개되는 것을 확인했다. 기존 교육지구 로딩, 구슬 탭·회전·원래 카메라 복원과 카메라 ViewModel 단일 인스턴스 검사도 통과했다.
