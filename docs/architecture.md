물리적 명패 제작·부착과 NFC 설치는 새 서비스의 필수 단계에서 제외한다. 기존 코드와 과거 모델은 후속 구현에서 전환 범위를 정하고 보존·정리한다. 상세 정책과 미정 항목은 [project.md](../project.md)를 따른다.

### #527 쇼케이스 설치 경로 구분 없는 즉시 공개 — 2026-11-19

사용자 최종 결정에 따라11월18일의 TF 전용 예외를 대체한다. 목록 심기는 TF/internal/직접 설치·Debug/Release 구분과 AI 결과 없이 같은 `publish-showcase-story`를 호출한다. AppTransaction 확인·JWS 전송·Apple 서버 검증 의존성을 제거한다. 검토 버튼은 기존 선택적 검수를 유지한다.

기존 초안·사진·삭제/정렬·오이 외형·카드 양면/표지 준비 및 리비전 확인을 재사용한다. Edge v2는 실제 Supabase 인증 토큰을 검증한 뒤 서비스 역할 전용 `oi_publish_showcase_story`를 호출한다. RPC는 저장된 세션·소유권·계정 제한·작성 상태·현재 입력/파일과 코인 규칙을 확인한다. 기존 `testflight_showcase_enabled`는 설치 경로와 무관한 서버 운영 스위치로 유지한다. AI 승인 기록을 만들지 않고 오류 시 초안을 보존한다.

목록/선택의 심기 버튼에서 `canPlant`·처리 중 비활성화·흐림을 제거하고 로딩 중에도 표시한다. 선택 진입/선택 대상을 검토 상태나 기능 플래그로 제한하지 않는다. 빈 목록·로그인·처리 중 탭은 안내하고 중복 공개를 차단한다. Figma `5400:7644`·`6101:9370`의 레이아웃·서체·원본 에셋은 유지한다. 운영 적용·검증·원복은 [운영 기록](testflight-showcase-publication.md)을 따른다.

### #388 이야기 공개 자동검수

`moderate-story` Edge Function은 기존 서버 `OPENAI_API_KEY`를 사용한다. `OPENAI_STORY_MODERATION_MODEL`을 별도 설정할 수 있으며 기본값은 학교 자료 분석과 같은 `gpt-4.1-2025-04-14`다. 작성자 세션과 제출 시 동의를 검증한 뒤 공개용 파일에만 90초 읽기 URL을 발급하고 제목·본문·오이 이름과 함께 OpenAI에 전달한다. 거부 사유는 위치·유형 코드로 제한하고 응답 저장을 끈다.

iOS 이야기 목록은 편집기를 열지 않고 저장된 기기 초안의 입력과 첨부를 확인한 뒤 검수를 요청한다. 편집기의 기존 검토 경로와 같은 초안 저장·첨부 동기화를 사용한다. ‘내용 검토 요청하기’를 누르면 해당 글의 검수를 시작한다. 승인 상태는 저장된 내용의 지문과 서버 검수 리비전이 일치할 때 표시한다.

AI 검수 전환 전에 운영자 검토를 요청한 글도 작성자가 목록의 내용 검토 요청으로 AI 검수를 시작할 수 있다. 서버는 기존 첨부를 읽어 검수하는 동안 운영자 검토 대기 상태를 유지한다. 검수 결과와 해당 글의 수정 가능한 초안 상태를 한 트랜잭션에서 기록한다. 기기 초안에 위치가 빠졌으나 작성자가 내 지도에 배치를 저장했다면 그 좌표를 복원해 검수 요청에 사용한다.

서버 전용 `oi_moderate_story`는 기존 제출 검사로 초안과 카드 구성을 확인한다. 검수 결과를 기록할 때 리비전과 파일 해시를 대조한다. 통과한 버전의 이미지를 비공개 초안에 연결한 뒤 승인 리비전과 해시를 보관한다. 작성자의 심기 요청에서만 새로 잠금을 잡아 승인본과 일치하는지 확인하고 공개한다. 검수 이후 수정된 초안은 다시 검토해야 한다. 검수 요청은 계정당 분당 5회로 제한한다.

#445 전환은 캠퍼스 공개 mutator에서 구버전 제출과 운영자 공개 호출을 차단한다. 검수 시점의 아트워크와 작성자 심기 경계는 유지한다. 교육지구는 같은 Edge Function의 인증·이미지 서명·OpenAI 호출을 사용하고 별도 서비스 전용 RPC에서 사진과 카드 양면의 정확한 리비전·새 동의·소유권을 검증한다. 교육지구는 검수 통과 즉시 게시하고, 결과 확인 실패 시 작성자가 같은 제출본의 검수를 다시 요청할 수 있다. 두 채널은 계정당 분당 5회 한도를 공유한다. 적용 순서와 전환 중 구버전의 동작은 [교육지구 공유 계약](education-shared-stories.md#자동검수-전환)을 따른다.


### #426 프로토타입 ver.4 중단 복구

검수 요청에 결과가 기록되기 전에 중단되면 이야기 목록에서 기존 `검토 전` 상태와 `내용 검토 요청하기`를 사용한다. 결과 조회가 실패한 경우에는 조회 실패를 표시하고 조회만 재시도할 수 있다. 기존 대기 글의 검수를 지원하는 DB 마이그레이션을 새 앱 배포 전에 적용한다. Edge Function의 요청 경로와 운영 기능 플래그는 기존 값을 사용한다.

삭제 확인, 스크래치 앨범 저장, 카드 요청 결정은 전송 전에 계정별 기기 저장소에 기록한다. 삭제된 서버 이야기의 ID와 소유자가 일치하면 기기 초안과 배치를 정리한다. 수집이 확인되면 해당 스크래치 화면에서 MY로 이동한다. 카드 요청은 알림 재진입 후에도 저장한 동일 결정으로 결과를 확인한다. 엽서의 앞면 또는 뒷면 다운로드가 실패하면 같은 카드에서 실패한 이미지만 재시도한다.

## 4. iOS 구조 제안

기능별 MVVM과 Repository 인터페이스를 사용한다. 단순 표시 화면은 View만으로 시작하고 비동기 작업이나 복잡한 상태가 생기면 ViewModel을 추가한다. 초기부터 별도 모듈·프레임워크나 모든 작업용 UseCase를 의무적으로 만들지 않는다.

```text
OiDonation/
├── App/                 # 앱 진입, 서비스 연결, 루트 탭, 링크 라우팅
├── Features/
│   ├── Home/
│   ├── Stories/
│   ├── Benches/
│   ├── Participation/
│   ├── MyDonations/
│   ├── Auth/
│   ├── Profile/
│   └── AR/
├── Domain/
│   ├── Models/
│   └── Repositories/    # 인터페이스
├── Data/
│   ├── Networking/
│   ├── DTOs/
│   └── Repositories/    # API 구현
├── Shared/
│   ├── DesignSystem/
│   ├── Components/
│   └── Utilities/
└── Resources/           # 에셋·3D 모델; 기존 리소스 위치는 유지 가능
```

| 계층 | 역할 |
| --- | --- |
| View | 레이아웃, 입력, 상태 표시 |
| ViewModel | 입력 검증, 작업 실행, 로딩·오류·재시도 상태 |
| Repository | 조회·저장 인터페이스; 실제 및 테스트 구현 교체 |
| APIClient | 인증 전달, 요청·응답, 공통 오류 처리 |
| 서버 | 권한 검증, 벤치 배정·신청 중복 방지, 공식 진행 상태 관리 |

제안하는 의존 방향은 View → ViewModel → Repository 인터페이스다. Data 구현은 Domain 인터페이스를 구현하고 AppContainer가 실제·테스트 구현을 연결한다. Domain은 SwiftUI나 서버 DTO에 의존하지 않는다. 서버 데이터는 DTO에서 앱 모델로 변환한다.

## 5. 데이터 모델과 상태

| 모델 제안 | 의미 |
| --- | --- |
| User | 로그인 사용자; 공개 프로필과 필요한 개인 정보 구분 |
| Bench | 승인된 기존 벤치, 위치, 공개·배정 가능 상태 |
| ParticipationApplication | 벤치 선택, 이야기·문구, 참여 신청 |
| DonationRecord | 학교에서 확인한 기부 기록; 앱 신청과 연결 방식 협의 필요 |
| Plaque | 승인 문구, 제작·부착·운영 상태 |
| Story | 공개 이야기, 사진, 플레이리스트, 공개 여부 |
| Reaction | 공감·감사 메시지, 신고·숨김 상태 |

기존 Donor와 User의 역할, Donation과 위 모델의 관계는 모델 담당자와 합의 후 결정한다. 한 신청에 여러 기부 기록이나 명패를 연결할 수 있는지 등 관계·수량은 명패 정책 확정 후 설계한다.

상태는 하나의 긴 enum으로 합치기보다 다음 영역을 구분하는 방향을 제안한다.

- 신청: 초안 → 제출 → 검토 → 승인 / 수정 요청 / 취소
- 납입 확인: 확인 대기 → 학교 확인 완료
- 명패: 제작 대기 → 제작 중 → 부착 완료

이는 초기 초안이다. 부분 납입·취소·환불·명패 재제작은 학교 절차를 확인해 전이 규칙을 추가한다. 신청 승인이 제작 시작이나 납입 완료를 의미하지 않는다. 명패 제작 가능 조건도 학교 및 팀 합의가 필요하다.

공식 상태의 원본은 서버에 두고, 사용자 클라이언트가 납입 확인 완료를 직접 수정하지 못하게 한다. 운영자 변경에는 변경자·시각·근거를 기록하며 민감한 증빙은 일반 공개 응답에서 제외한다.

## 6. 화면 이동과 탭바

전체 앱에서는 RootTabView가 홈·내 기부·후원·벤치지도와 별도 카메라 버튼을 관리하는 방향을 제안한다. HomeView는 홈 콘텐츠에 집중한다. 홈 전체 미리보기는 루트 화면으로 구성한다. 현재 홈 구현을 즉시 재구성하라는 지침은 아니다.

각 탭은 자신의 NavigationStack과 경로를 유지한다. AppRouter는 벤치·스토리 ID 기반 링크를 해석하고, 미공개·삭제 콘텐츠와 로그인 필요 상태를 처리한다. 로그인 없이 공개 이야기를 탐색하고 참여 신청 등 필요한 시점에 로그인하도록 설계한다.

## 7. NFC와 AR

NFC에는 공개 벤치 URL을 기록한다. 개인정보·로그인 토큰은 넣지 않는다. 앱 설치 여부에 따른 웹 안내와 앱 링크 처리를 함께 설계한다. URL 형식과 운영 도메인은 미정이다. NFC는 기부 확인 수단이 아니다.

AR은 카메라 권한, 세션, 캐릭터 선택, 사진 합성을 독립 기능으로 관리한다. 화면 진입·종료에 맞춰 세션을 시작·해제하고 권한 거절 및 기기 미지원 상태를 표시한다. 촬영 사진은 기본적으로 기기에 저장하며 서버 업로드는 사용자 선택과 별도 정책이 필요하다.

## 8. 서버·운영자·인증

운영자 최소 기능은 신청·문구 검토, 학교 확인 결과 연결, 명패 제작·부착 상태 변경, 벤치 공개 관리, 신고 콘텐츠 처리다. 기존 웹·서버 구조를 조사하고 재사용할 부분을 결정한다. 기술 스택을 이 문서만으로 새로 확정하지 않는다.

사용자·운영자 권한과 상태 전이는 서버에서 검증한다. 참여 신청 재전송은 중복 생성되지 않도록 처리하고 벤치 배정 경쟁은 서버 트랜잭션·제약으로 해결한다. 업로드 크기·형식, 공개 범위와 삭제 정책을 정의한다.

로그인 공급자, 서버 토큰 발급 방식과 세션 갱신은 API 계약에서 합의한다. 앱 인증 토큰은 Keychain 등 적절한 저장소에 보관하고, 서버 비밀키는 앱과 저장소에 포함하지 않는다. 학교에서 이미 수집하는 결제·개인정보는 앱에서 중복 수집하지 않는다.

행동 로그에서 공식 사이트 이동, 신청 제출, 학교 확인 완료를 구분한다. 개인정보·이야기 본문·사진·토큰은 분석 로그에 넣지 않는다. 외부 사이트의 실제 납입 전환율은 연동 없이 앱 로그만으로 측정할 수 없다.

## 9. 개발 환경과 검증

공식 배포 계정·Bundle ID는 팀이 정하고 개인 개발 서명은 로컬 설정으로 분리하는 방향을 검토한다. 인증서 개인 키·p12·토큰과 개인 설정은 커밋하지 않는다. 개발·운영 서버 주소와 각 앱 ID에 연결된 기능 설정도 구분한다.

검증 우선순위는 신청 입력·재시도·중복 방지, 납입 상태 오표시 방지, 운영자 권한, 벤치 배정 충돌, 링크 라우팅이다. Repository 테스트 구현으로 로딩·빈 상태·오류를 재현하고 화면 빌드 및 주요 흐름을 확인한다. AR·NFC는 실제 기기에서 추가 검증한다.

## 캠퍼스 홈 디자인 전환 — 2026-10-26

사용자 요청으로 전체 iOS 앱의 루트를 3D POSTECH 캠퍼스 홈으로 전환했다. `RootTabView`는 이름을 유지하되 한 `NavigationStack`과 `CampusStoryStore`를 소유하고 `CampusDestination`의 화면 등록을 담당한다. `HomeView`의 지도 마커는 콜백으로 루트의 `NavigationPath`에 요약 ID를 추가하며, 지역 목록과 요약의 자세히보기 링크도 같은 경로를 사용한다. 요약을 별도의 `navigationDestination(item:)` 상태로 띄우지 않는다. 프로필 시트는 독립 스택을 유지하므로 뒤로가기는 해당 진입 경로로 복귀한다. 기존 AR은 홈의 독립 카메라 버튼에서 모달로 열리고, 내 기부·후원·벤치·사진 테스트는 프로필 메뉴로 이동했다. develop의 공개 링크 파서와 App Clip 구현을 유지한다. 원격 App Clip 후속 작업(#79)은 별도 브랜치에서 관리한다.

`Features/Campus/Scene`은 OiCampus의 custom mesh·높이 필드·좌표 변환을 재사용한 RealityKit non-AR 지도다. 카메라 이동과 확대·회전·기울기 조절은 로컬이며, 캐릭터 마커는 Figma 이미지 버튼을 3D 지점에 투영한다. 지도와 마커의 공통 부모에 제스처를 등록하고, 한 손가락 이동·두 손가락 드래그 회전 및 기울기·핀치·비틀기를 변화량으로 합성한다. 2026-11-04 사용자 요청으로 비틀기의 부호를 수정했다. 화면 오른쪽 손가락을 아래로, 왼쪽 손가락을 위로 움직이면 지도도 시계 방향으로 회전한다. 지도 제스처끼리만 동시 인식하며 손가락 수 전환 시 드래그 기준을 초기화한다. 외부 서버·GPS 사정거리·3D 캐릭터 자율 이동은 아직 연결하지 않았다. 큰 캠퍼스 자산은 전체 앱에만 포함한다.

예시 스토리는 실제 기부 Repository와 분리된 `CampusStoryStore`에 둔다. 수집은 기기 로컬 UserDefaults로 저장하고, 중복 탭을 무시하며 목록·요약·상세·프로필이 상태를 공유한다. 수집과 실제 기부 확인을 연결하지 않는다. `project.md`의 공식 기부 절차 원칙은 유지한다. 구현 파일·디자인 참조·자산 출처·검증 범위는 [캠퍼스 디자인 문서](../apps/ios/docs/campus-redesign.md)를 따른다.

## 농부·오이 수집 및 증빙 승인 — 2026-10-27 기획 반영

다음은 최신 기획을 구현하기 위한 **설계 경계·제안**이다. 이번 문서 변경으로 아래 API·데이터 모델이 구현되지는 않는다.

- 농부 아바타와 계정, 기부자가 등록한 오이·스토리·공개 위치, 이용자의 수집 기록·카드, 개인 착용 아이템을 구분한다. 원본 오이와 수집 사본의 외형 변경 권한은 후속 합의가 필요하다.
- 증빙은 공개 사진 저장소·스토리 응답과 분리하고 운영자 검토용 접근 권한을 둔다. 가상 자료로 접수·검토·보완·작성 승인 흐름을 검증한 뒤 실제 자료를 받는다.
- 증빙 검토 상태와 작성 권한을 서버에서 검증하는 방향으로 설계한다. 운영자 승인 버튼이나 클라이언트 상태만으로 작성 권한을 만들지 않는다. 운영자·처리 시각·근거를 기록하고 승인당 작성 수량은 정책 합의 후 제한한다.
- 학교 공식 납입 확인 필드와 팀의 증빙 검토 결과를 합치지 않는다. 기존 `DonationRecord`·`DonationStatus`가 자동으로 새로운 작성 승인을 나타낸다고 가정하지 않는다.
- 지도와 AR은 동일 오이·스토리 ID를 참조한다. 위도·경도, 3D 지도 좌표와 AR 높이·방향의 연결 및 실제 위치 정확도는 별도 검증한다. 현장 발견과 로컬 수집 UI 구현을 구분한다.

## 15. iOS 벤치지도 MapKit 적용 — 2026-10-16 / #80

사용자 요청으로 BenchesView의 목록을 SwiftUI MapKit 지도로 교체했다. POSTECH 캠퍼스 개요를 기본 영역으로 표시하고 이동·확대·축소·회전·기울이기, 순정 나침반·축척, 일반/위성 전환과 캠퍼스 복귀를 제공한다. 내 위치 버튼에서만 사용 중 위치 권한을 요청하며 UserAnnotation과 사용자 위치 카메라를 연결한다. 거부·제한·위치 조회 오류·20초 시간 초과 안내와 설정 이동을 제공하며 화면 이탈·백그라운드 전환 시 일회성 위치 요청을 취소한다. 위치를 서버에 전송하거나 백그라운드 권한을 요청하지 않는다.

### 2026-11-18 작업: 포토카드 기울기 효과 (#493)

`OiStoryCompletionView`의 카드 외곽에만 Core Motion 기반 기울기를 적용한다. 화면을 열거나 다시 활성화한 자세를 기준으로 상대 기울기를 평활화하고 축별 최대 4°로 제한한다. App Clip의 `ScratchPostcardView`는 긁기가 끝난 뒤 UIKit `UIInterpolatingMotionEffect`를 별도 외곽 계층에 적용하며 기존 뒤집기 transform과 합성한다. 본 앱이 공유하는 수집 화면에는 이 UIKit 효과를 켜지 않는다.

화면 이탈·비활성·동작 줄이기·가리는 시트에서 구독 또는 효과를 제거하고 정지 상태로 되돌린다. 센서 미지원·오류에서도 기존 카드 열람·뒤집기는 유지한다. 카드 파일·서버·공개·수집 계약은 변경하지 않는다. App Clip의 Core Motion은 [공식 지원 대상이 아니며](https://developer.apple.com/documentation/appclip/choosing-the-right-functionality-for-your-app-clip), UIKit 모션 효과의 실제 App Clip 동작과 두 방식의 물리 센서 반응은 시뮬레이터 빌드·합성 입력 검사만으로 확정하지 않는다.

### 2026-11-16 적용: 앱 내부 기능 사용 설정 (#379)

- 사용자 확정 범위: 시스템 권한과 별개로 이 기기의 알림·위치·카메라·사진 저장 사용 여부를 유지한다.
- `OiFeatureUsage`는 UserDefaults 기반 선택을 보관하고 변경을 관찰 가능 상태 및 NotificationCenter로 전달한다. 별도 선택 전에는 기존 동작을 유지한다.
- 설정 토글은 시스템 권한 허용 후 로컬 사용 여부만 변경한다. 위치/AR 서비스는 OFF 이벤트에서 진행 중인 작업을 중단하고 새 작업 진입도 차단한다. 사진 저장 서비스는 권한 요청 전후 사용 설정을 확인한다.
- 알림 OFF는 예약·표시 알림을 정리하고 원격 알림 등록을 해제한다. 현재 앱에는 알림 예약/푸시 등록·발송 경로가 없으며 신규 발송 기능은 범위에 포함하지 않는다.
- 인증 계정/프로필/서버 권한을 변경하지 않으며, 앱 내부 OFF로 iOS 시스템 권한을 해제하지 않는다.

2026-11-18 #477: 설정 권한 토글을 기존 ON/OFF 색상의 시스템 `UISwitch`로 교체하고, 이미 허용된 기능은 전체 권한 조회 없이 선택값을 즉시 저장한다. 미허용 권한의 요청·설정 안내와 기존 기능 차단은 유지한다. [색상 비교와 검증](../apps/ios/docs/verification/settings-toggle-477/README.md).

2026-11-16 커스텀 로딩 후속: STEP 2는 선택 모델 하나만 준비하고, STEP 3/4는 단일 원본·동시 로딩 공유 캐시에서 독립 엔티티를 복제한다. 지도/AR 직접 로딩은 유지한다. `OiPortraitImages` 액터는 PNG 인코딩·복원·투명 검사·매트 합성을 직렬로 수행하고 마지막 검증 이미지만 재사용한다. 저장된 유효 PNG가 있으면 캡처 장면을 만들지 않으며, 배치 편집의 숨은 캡처 장면은 회전 완료 후 해제한다. 메시·텍스처 해상도·흑백 알파 복원·초안/서버 계약은 보존한다. 메모리 경고·백그라운드·열 상태 변화에서 캐시를 비운다. [측정과 회귀 검사](customization-loading-performance.md).

2026-11-16 #392 사용자 후속: 메인 지도 개요는 오이 위치·구역 집계만 유지하고 공개/본인 오이의 버튼·사진 요청·모델 로딩을 만들지 않는다. 이야기 목록의 지역 화면에서만 표시하며 화면 밖 인스턴스를 제거하고 공개·본인 원본 캐시를 각각 최대 8개로 제한한다. 본인 모델 준비는 단일 Task로 공유하고 취소·계정/외형 변경·목록 닫기 이후 결과를 적용하지 않는다. 기존 브랜치의 2초 유휴 프레임 유지·터치 복귀와 교육지구 근거리 지연 준비를 보존한다. 건물 선택은 카메라 투영과 단일 로컬 경계 상자의 교차로 검사해 정지 화면의 첫 터치에서도 동작하며, 안내 콘텐츠 버튼은 기존 체험 진입 상태를 공유한다. 세부 조건과 실측 결과는 [지도 발열 개선 기록](campus-map-thermal-392.md)을 따른다.

2026-11-16 엽서 사진 표시 최적화: `CampusPostcard` 전용 캐시는 원본 해상도·PNG 알파·배경 메타데이터를 보존하고 디코딩/표시 준비와 디스크 I/O를 별도 actor에서 수행한다. 같은 경로의 요청을 공유하며 메모리 16MiB·2개, 세대별 디스크 64MiB·5분 만료를 적용한다. 계정/공개 목록 변경은 진행 작업과 캐시 세대를 무효화한다. 목록 진입 2.5초 후 첫 앞면 한 장만 순차 사전 준비하고 저전력/높은 열 상태에서는 시작하지 않는다. 뒷면은 뒤집을 때 요청한다. 완성 PNG와 이야기 사진 경로에 적용하며 운영자 검토와 원본 내보내기는 기존 다운로드를 유지한다.
