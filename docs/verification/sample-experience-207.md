# 이야기·AR 체험 — #207

## 결정과 구현

- 2026-11-07 사용자 승인: [Figma 예시](https://www.figma.com/design/nEDJaJBFrdzBCa1WcgADHH?node-id=2876-8316)를 참고용으로 사용. 상세 `2450:4928`의 본문·태그, 기존 6냥이 이미지와 카드 컴포넌트를 재사용한다. 전체 지도 재설계나 Figma의 가상 기부 횟수는 범위 밖이다.
- 본 앱: 지도 오른쪽 위 **체험하기** → 이야기 → **AR 체험 시작** → 카메라 권한 → 30초 안에 오이 3개 찾기 → **체험 카드 모으기** → 완료. 지도 로드 실패 시에도 체험 버튼을 제공한다.
- App Clip: 첫 화면 **이야기·AR 체험** → 같은 흐름. 특정 이야기 링크로 진입했다면 **이야기 목록** 또는 **처음으로**에서 첫 화면으로 돌아갈 수 있다.
- 모든 사용자에게 같은 경로가 보인다. 로그인·기부·위치·공개 이야기 존재 여부에 의존하지 않는다. AR 미지원 기기/권한 거부는 기존 안내와 복귀·설정 경로를 사용한다.
- 예시 수집은 체험 화면 내 메모리만 변경한다. 종료 시 초기화되며 서버 호출·계정 도감·App Group 보관함·기부 기록·작성 승인과 무관하다. 예시 ID는 UUID가 아니며 공유 보관함의 저장 함수도 거부한다.
- 실제 이야기 목록·기부·로그인·기존 계정 수집은 기존 경로 그대로다. 새 사진·폰트·대형 리소스는 추가하지 않았다.

## 검증

- `run-app-clip-checks.sh`: 예시 저장 거부 및 재개 후 기록 없음, 실제 카드 중복/손상/삭제, 공개 이야기 조회·AR 상태 전환 회귀.
- `run-campus-checks.sh`, `run-architecture-checks.sh`, `run-my-checks.sh`: 기존 예시 본문·모델·도감 경계.
- 위 4개 셸 검사 모두 통과. App Clip 검사에는 기존 Swift 5 모드의 actor 경고가 있으며 실행은 통과했다.
- Xcode 27 / iOS 27.2 Simulator, `OiFlowChecks`: `testSampleExperienceCaptures` 1개 통과, 실패 0. 375×667·402×874·440×956·접근성 글자 크기 5에서 이야기/수집 전/수집 완료 12개 캡처를 생성하고 작은 화면과 큰 글씨를 육안 확인했다.
- 본 앱 및 Clip을 각각 실행하여 체험 입구 → 이야기 → AR 소개 → 시작 → AR 미지원 안내 → 돌아가기를 확인했다. Simulator는 ARWorldTracking을 지원하지 않으므로 실제 카메라 플레이·권한 허용·게임 성공은 실기기 미검증이다. 성공 결과 뷰는 가상 상태로 렌더링 검증했다.
- 본 앱의 Simulator 검증은 무서명 빌드여서 계정 Keychain 접근 안내가 나타났다. 체험은 계정 없이 진입 가능했다. 실제 로그인/배포 서명 성공을 의미하지 않는다.
- AR 미지원 안내 확인 중 공통 AR 뷰의 최소 높이가 제목/닫기 버튼을 겹치게 하는 문제를 수정했다. 공통 상태 화면이 전체 영역을 사용하도록 한 줄 보정했다.
- `OiDonation` Release Simulator 빌드 성공, App Clip 포함. 기기용 배포 아카이브·Apple 검증은 수행하지 않았다.

## 제출 전 확인

AR 지원 실기기에서 카메라 허용/거부, 3개 찾기, 체험 수집 후 닫기·재진입 초기화를 확인한다. App Store 심사 메모에 위 경로와 체험/실제 데이터 구분을 명시한다. 이 PR은 업로드·Apple Validate App·실제 제출을 수행하지 않는다.
