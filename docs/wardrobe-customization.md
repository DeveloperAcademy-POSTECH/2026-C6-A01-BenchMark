# 원본 몸체에 맞는 오이 옷장

2026-11-03 · Figma `2945:2969`

## 커스텀 오이 현장 테스트 — 2026-11-04

아래는 기존 테스트 경로의 구현·검증 기록이다. #141에서 앱의 현장 테스트와 옷장 바로 체험 진입점을 제거했다. 기기에 이미 저장된 테스트 사본을 자동 삭제하지 않는다.

1. **오이 커스텀 → 캠퍼스에 테스트 배치**를 연다. 실제 작성 또는 Debug의 지도 `+ → 오이 옷장 바로 체험`에서 시작한다.
2. **장소 찾기**로 주변을 확대한 뒤 건물 밖 바닥을 누른다. 위에서 보기·미세 이동으로 발 위치, 방향 슬라이더로 방위를 정한다. **오이 보기**는 위치를 바꾸지 않고 착장을 가까이 보여준다.
3. **이 배치로 저장**을 누른다. 한 개가 있으면 교체 확인을 표시한다. 저장 후 위치/방향/외형 변경 시 다시 저장할 때까지 AR 진입을 막는다.
4. 실제 위치에 도착하면 **지도 홈 → POSTECH 농장 길게 누르기 → 내 오이 현장 테스트 → 현장 AR로 보기**로 재개한다. 카메라·정확한 위치 권한이 필요하다.
5. 목표 25m 이내·GPS 오차 15m 이하·최신 위치·정상 카메라 추적 조건에서 표시된다. 바닥과 주변을 비추고 GPS 위치가 어긋나면 **직접 바닥 보정 → 실제 바닥 탭**으로 조정한다. 보정은 이번 세션에만 유지된다.

GPS/나침반에는 수 m 이상 오차가 있을 수 있다. 지도 좌표 선택의 정밀도가 AR 정합 정확도를 보장하지 않는다. 현장 지리 추적 지원은 런타임에 확인하고 미지원이면 GPS 모드를 사용한다. 실제 캠퍼스의 위치 오차·발 높이·앵커 흔들림은 기기 현장 검증이 필요하다.

### 저장과 표시 범위

**기기 전체 테스트 한 개**를 Application Support의 `OiDonation/wardrobe-field-trial-v1.json`에 보관한다. 계정별 작성 초안과 독립적이며 로그아웃 뒤에도 남는다. 사진·색상·데님·좌표·방위를 저장하고 공개 API/다른 기기로 보내지 않는다. 옷장 체험 자체는 메모리 전용이지만 명시적으로 저장한 현장 테스트 사본은 재시작해도 유지된다. 화면에서 교체/삭제를 안내한다.

사진은 기존 축소·압축 데이터만 보관하고 합성 아틀라스는 저장하지 않는다. JSON 최대 12MiB, 원자적 쓰기, iOS 파일 보호, 백업 제외, 손상 파일 덮어쓰기 방지를 적용한다. 리소스·사진 로드 실패나 지도 밖 좌표는 표시/저장을 중단하며 재시도 또는 명시적 삭제로 복구한다.

`OiWardrobeAsset`의 같은 의상 조립 경로를 옷장·카드·지도/AR에서 공유한다. 배치용 루트만 높이 150cm·발바닥 0으로 정렬하고 원본 메시·핏·사진 UV를 보존한다. 일반 지도 마커 크기·공개 AR의 기존 프리셋은 유지한다.

### 검증

- 서비스 검사: 색상·데님·앞뒤 사진 변형/바이트·좌표/방향 재시작 복원, 교체·삭제, 유효하지 않은 값 거부, 손상 파일 보존 통과.
- Debug `-wardrobe-field-check`: 사진 후드티+데님과 한 벌 4종을 실제 번들에서 조립해 0/90/180/270도에서 높이 1.5m·발바닥 0 확인. 지도 단위 환산 및 렌더러 재생성 후 좌표/발 위치 검사 통과. 검사 자체는 파일/서버 쓰기 없이 유효한 지도 지점의 미저장 예시만 연다.
- 시뮬레이터: 커스텀에서 진입, 장소 검색, 예시 위치 저장, AR 미지원 안내, 재실행 후 일반 지도 홈에서 재개, 10cm 이동 시 AR 비활성화와 교체 확인을 검증했다. 지도 바닥 직접 터치와 실제 GPS/카메라/바닥 고정은 자동화에서 완료하지 못했으며 기기 확인이 필요하다.
- 최종 시뮬레이터/실기기 Debug 빌드 통과, Jun iPhone(iOS 26.7.2)에 업데이트 설치 완료. 지도에서 사진 후드티·데님 코디를 가까이 확인하고 AR 화면 왕복 후 저장 상태가 유지되는 것을 확인했다. 화면 증거는 워크스페이스 `output/oi-wardrobe-field-test-20261104/field-map.jpg`에 있다. 실제 캠퍼스 AR 정합은 아직 검증하지 않았다.

## 사용

- 실제 작성: 이야기 작성 → 위치 → **오이 커스텀**. 상의/하의/신발/세트와 색상을 고른다. 정면·좌·우·뒤 버튼, 드래그 회전, 핀치 확대를 지원한다.
- 실제 작성의 의상·색상은 계정별 기기 초안에 자동 저장된다. 공개 미리보기/지도/AR에는 기존 서버 프리셋이 사용된다. 서버 payload와 승인 흐름은 변경하지 않았다.

## 조합

| 상의 | 긴바지 조합의 몸체/하의 | 반바지 조합의 몸체/하의 |
| --- | --- | --- |
| 흰 반팔 티 | base / base | shorts / shorts |
| 흰 후드티 | hoodie / hoodie | hoodie / shorts |
| 흰 가디건 | cardigan / cardigan | cardigan / shorts |
| 포스텍 과잠 | postech / base | postech / shorts |

몸체와 상의는 같은 생성 원본에서 가져온다. `base`는 흰 반팔티·흰 긴바지 원본이다. 원래의 검정 청바지와 삭제 요청된 공룡/곰돌이 모델은 사용하지 않는다. 교차 하의 네 조합은 허리 부분만 상의 원본의 경계로 완만하게 맞췄으며 무릎 아래/반바지 밑단·신발 위치는 유지했다. 신발은 원래 형상의 흰 재질이다.

모델은 상의 기준 몸체까지 함께 교체한다. 하나의 고정 몸체에 모든 옷이 호환된다는 뜻은 아니다. 포즈가 고정된 미리보기이며 리깅/동작 중의 충돌 검증은 포함하지 않는다.

## 색상과 리소스

- 계열 토글 없이 뉴트럴·파스텔 12색을 함께 표시한다. 뉴트럴: 화이트·아이보리·오트밀·토프·스톤·차콜.
- 파스텔: 세이지·민트·스카이·라벤더·블러시·버터.
- Top/Bottom/Shoes 별로 재질 tint를 적용한다. 피부에는 색을 적용하지 않으며 포스텍 과잠의 원래 로고/색상은 보존한다. 텍스처 파일을 색마다 복제하지 않는다.
- 8개 USDZ 합계 **93,805,866 bytes (93.8 MB)**. 각 약 9.6–14.1 MB, 9.8만–10.4만 삼각형, 텍스처 최대 1024px. 생성 직후 앱용 묶음 약 247.4 MB에서 경량화했다.
- 장면은 현재 조합 하나만 보유하며 비활성화/화면 이탈 때 모델·로드 작업을 해제한다. 이전 선택의 로딩 결과가 뒤늦게 현재 선택을 덮지 않도록 세대 번호와 요청 ID를 확인한다.
- 원본 USDZ/Blender 파일은 변경하지 않았다. 소스는 워크스페이스 `meshy_output/compatibility-audit-20261101/trial/separated/*-parts.blend`이다. 새 Meshy 생성이나 크레딧 사용은 없다.

## 재현과 검증

`tools/wardrobe/prepare_wardrobe.py`를 Blender background Python에서 실행한다. 인자는 워크스페이스 루트, `Resources/Wardrobe` 출력 폴더, 검증 렌더 폴더다. 이어 `verify_wardrobe.py -- WORKSPACE`로 패키지를 다시 열어 검사한다. 현재 검증 스크립트의 프로젝트 경로는 이 작업 checkout을 기준으로 한다.

증거는 워크스페이스 `output/oi-compatible-wardrobe-20261103/`에 저장했다.

- `manifest.json`: 원본/출력 SHA-256, 몸체와 하의 출처, 높이, 파일 크기, 삼각형 수.
- `validation.json`: 모든 USDZ를 다시 열어 높이(150cm, 오차 0.03cm 미만), Y-up/미터 단위, UV, 역할 이름, 모든 텍스처 의존성 검사 통과. 원본 파일 해시 유지 확인.
- 32장 실제 메시 렌더와 `contact-0.jpg`, `contact-1.jpg`: 8개 조합의 정면·좌·우·뒷면. 해당 네 방향에서 목·손목·허리·발 경계의 눈에 띄는 벌어짐/관통을 확인했다. 모든 각도와 향후 애니메이션에서 교차가 절대 없음을 수학적으로 보장하는 검사는 아니다.
- iPhone 17 / iOS 26.5 시뮬레이터: 8개 조합 모두 로드 로그 확인, 스카이 후드티/버터 반바지/차콜 운동화 분리 염색, 카드 왕복 후 선택 유지, 포스텍 과잠 반바지 뒷면, 지도 + → 옷장 체험 진입, 세트 이미지 교체, 모델 영역에서 세로 스크롤 확인.
- `run-oi-service-checks.sh`: 기존 초안 호환, 미지원 의상 ID fallback, 의상과 3개 색상 계정별 재시작 복원, 기존 공개 payload/승인 경계 유지 검사 통과.

Debug 빌드/실행 통과. 실제 기기 설치, 사용자 계정의 공개 제출, 지도/AR 외형 공유는 이번 검증에 포함하지 않았다.


## 사진으로 옷 꾸미기 — 2026-11-04

오이 커스텀에서 **상의 또는 하의 → 사진으로 옷 꾸미기 → 사진 추가 → 적용**으로 연다. OiCharacterLab의 사진 편집 기능을 현재 몸체별 의상 조합에 이식했다.

- 흰 반팔티·후드티·가디건·긴바지·반바지 5개 아이템 지원. 포스텍 과잠은 로고/원래 재질을 유지하고, 운동화는 기존 색상 선택을 제공한다.
- 앞면/뒷면만 편집한다. 당시 아이템마다 총 8장까지(2026-11-05부터 새 추가는 면당 2장) 다중 선택, 선택한 사진의 한 손가락 드래그, 두 손가락 핀치 확대·축소와 비틀기 회전, 면 이동, 복제/삭제, 앞뒤 순서 변경을 제공한다. 위치·크기·회전 슬라이더는 제거했다. 캔버스 밖에서 세로로 스크롤해 아래 편집 도구를 연다.
- 현재 선택한 사진이 움직일 때 3D를 갱신한다. 선택한 옷 색을 사진 뒤 바탕으로 사용하며 사진 원색에는 옷의 tint를 곱하지 않는다. 옷 변경·세트 선택 후 돌아오면 해당 아이템 사진이 유지된다.
- 적용 전 변경은 편집기 내부 상태이며 취소하면 버린다. 지우기는 해당 아이템 디자인만 제거하고 원래 메시/재질을 다시 표시한다. 기존 초안의 색상과 사진 없는 데이터도 복원된다.

### 자산과 용량

`tools/wardrobe/prepare_photo_uv.py -- REPORT_DIRECTORY`를 Blender Python으로 실행한다. 이미 맞춘 8개 조합의 실제 Top/Bottom 메시에서 총 14개 사진용 USDZ(과잠 상의 제외)와 앞/뒤 JSON 윤곽을 생성한다. 원래 위치·삼각형·법선은 보존하고 UV/재질만 교체한다. 현재 기본 묶음 외 추가 리소스 **23,329,240 bytes**. 전체 캐릭터/텍스처를 다시 복제하지 않는다.

앞뒤 분류는 주름의 면 법선 대신 깊이와 투영 가시성으로 정한다. 측면 경계·소매 안쪽처럼 양 방향에서 동시에 보이는 면에는 앞뒤 이음선이 남는다. 한 장의 사진이 360도로 끊김 없이 이어지는 원통 매핑은 아니다. 입력 패키지 SHA-256 유지, 모든 14개 사본의 꼭짓점 위치/면 인덱스 및 UV 길이 검증, 위치 오차 1µm 미만을 확인했다. 상세 수치는 워크스페이스 `output/oi-compatible-wardrobe-20261103/photo-uv-validation.json`에 있다.

사진은 ImageIO로 긴 변 768px 이하로 축소하고 불투명 JPEG(품질 0.8), 투명 PNG로 다시 인코딩한다. EXIF/GPS 등 원본 메타데이터와 전체 해상도 파일은 저장하지 않는다. SHA-256 키로 아이템 간 중복 저장을 줄이고 마지막 참조를 지울 때 함께 제거한다. 한 소스 최대 1MiB, 초안 전체 소스 최대 8MiB다. JSON의 Base64 부피는 이보다 약 1/3 늘 수 있다. 편집 중 1024×512, 적용 후 2048×1024 아틀라스는 메모리에서만 생성한다. 50ms 병합 갱신으로 입력 중 불필요한 렌더를 줄인다.

### 저장 경계와 검증

`OiWardrobeLook.artwork`의 사진/배치는 기존 계정별 `OiDraftVault` 초안 안에 함께 저장한다. 별도 공용 사진 폴더가 없어 다른 계정/초안의 파일을 삭제하지 않는다. 원자적 저장·iOS 파일 보호·백업 제외·계정 병합/삭제는 기존 vault 경로를 따른다. 공개 API payload, 서버 업로드, 지도/AR에는 보내지 않는다.

검증:
- iPhone 17/iOS 26.5 Debug 빌드·실행 성공. 기존 동시성 등 경고는 남아 있다.
- 사진 보관함의 기본 풍경 2장 동시 선택 및 실시간 적용, 앞/뒤 배치, 드래그, 복제/삭제, 취소 시 2장 유지, 재편집 복원 확인.
- 지원 상의 3종/하의 2종 사진 적용, 다른 의상에서 돌아온 뒤 디자인 유지, 상·하의 동시 적용, 삭제 후 원래 재질 복구 확인.
- 서비스 검사: 기존 JSON 호환, 계정별 재시작 복원(앞뒤 변환/사진 바이트 포함), stale write 방지, 레이어/변형/용량 검증, 아이템 간 소스 공유·삭제 생명주기, 실패한 갱신의 원자성 통과.
- 실기기 멀티터치·메모리 프로파일링과 서버/지도 공유는 이번 검증 범위에 포함하지 않았다.

### 사진 보관함 표시 안정화 — 2026-11-04
