# 교육지구 앱·웹 이야기 공유 — #378

2026-11-16 사용자 확정: 교육지구에서 작성한 이야기는 교육지구 건물의 구슬에서만 공유한다. 캠퍼스 지도·AR 위치, 오이 배치, 기부·작성 승인·수집 기록을 만들지 않는다. 기존 캠퍼스 이야기는 유지한다.

## 사용자 흐름

- 웹의 ‘나의 이야기 남기기’와 앱 교육지구 체험의 같은 버튼을 사용한다. 테마 → 감정 → 공개 이름 → 제목(45자) → 본문(UTF-8 1,500byte) → 사진 순서다. 이번 UI는 사진 1장, 서버 계약은 1~3장이다.
- 로그인 없이 승인된 이야기와 카드 앞·뒷면을 볼 수 있다. 로그인한 작성자는 비공개 초안 저장과 공개 검토 요청을 할 수 있다. 공개·사용 권한 동의는 미리 체크하지 않는다.
- 웹은 Google OAuth/PKCE와 탭 세션 저장소를 사용한다. 앱은 기존 Apple/Google 네이티브 계정을 그대로 사용한다. 운영 Apple 설정은 네이티브 번들 ID만 등록돼 있으므로 웹의 Apple OAuth 버튼은 제공하지 않는다. Apple 가입자는 앱의 기존 계정 연결 절차로 Google을 연결한 뒤 웹에서도 같은 계정을 사용한다. [Supabase Apple 웹 설정](https://supabase.com/docs/guides/auth/social-sign-in/auth-apple).
- ‘이야기 둘러보기’ → ‘내 이야기’에서 서버 초안을 이어 쓴다. 기기 입력은 계정별 로컬 초안으로 자동 보관하고, 서버 저장 완료/실패를 구분한다. 저장·업로드 응답 유실은 일치하는 리비전·바이트·카드 ID일 때만 복구한다.
- 운영자는 같은 목록의 ‘공개 검토’에서 원본 양면과 미리보기 양면을 모두 확인한 뒤 공개 승인한다. 일반 사용자에게 검토 메뉴를 표시하지 않으며 서버도 권한을 검사한다. 신고는 운영자만 읽는다.
- 공개 후 수정은 먼저 비공개 초안으로 되돌린다. 삭제·계정 제한·탈퇴·작성 중지는 서버에서 적용한다. 공개 해제 후 새 URL 발급은 중단되지만 이미 발급한 URL은 최대 300초 유효할 수 있다.

## 데이터와 API

`benchmark_private.oi_education_stories`와 `oi_education_reports`는 직접 읽기·쓰기를 허용하지 않는다. 기존 정식 계정·운영자·감사·작성 중지·콘텐츠 제한 정책을 재사용한다. 소유자는 Auth 구성원을 참조하고, 권한 판단 때 대표 계정을 확인해 계정 통합을 보존한다. 기존 탈퇴 흐름이 모든 구성원의 저장 파일과 Auth 계정을 제거하며 이야기·신고·대상 감사 자료도 정리된다.

| RPC | 용도 | 권한 |
| --- | --- | --- |
| `oi_education_stories` | 공개/내 이야기/운영자 목록, 페이지당 최대 50개 | 공개만 익명, 나머지 소유자/운영자 |
| `oi_education_story` | 현재 상태와 카드 경로 조회 | 공개/소유자/운영자 |
| `oi_education_mutate` | save, attach_media, submit, reopen, delete, review | 로그인, review는 운영자 |
| `oi_education_report` | 공개 이야기 신고 | 로그인 |

`oi_education_json`은 공개 DTO에 교육지구 채널과 카드 경로를 넣고 동의·원본 소유자 필드는 제외한다. 파일 경로의 Auth UUID는 저장소 식별자로 제공한다. 공개 카드 이미지·본문·표시 이름은 운영자가 검토하며 원본 작성자의 로그인·개인 프로필은 공개하지 않는다.

## 카드와 비공개 Storage

기존 `oi-story-media` 비공개 버킷에 `owner/education/story/`를 접두사로 사용한다. 캠퍼스용 경로·Storage 제한 정책을 보존하고 교육지구 분기만 추가한다.

- 사진: `photos/<사진 바이트 해시 UUID>.jpg` 또는 `.png`
- 앞면 원본: `card/<snapshot>.png`
- 뒷면 원본: `card/<snapshot>/back.png`
- 양면 미리보기: `card/<snapshot>/front-preview.png`, `back-preview.png`

앞·뒷면 원본 1086×1506, 미리보기 724×1004의 PNG 형식 2 계약이다. 웹에서 동일한 글·사진으로 네 이미지를 생성하고, 앱·웹 모두 이 파일을 표시한다. 네 파일의 바이트 해시로 snapshot ID를 정하며 업로드는 덮어쓰지 않는다. 사진과 네 파일이 모두 존재하고 MIME·8MiB 이하·동의·리비전이 일치해야 검토 접수한다. 운영자는 원본과 미리보기 내용의 일치도 확인한다. 미참조 부분 업로드는 비공개로 남으며 자동 청소 정책은 추가하지 않았다.

## 앱 브리지와 성능

- 로컬 HTML은 허용한 네 RPC, 교육지구 파일 업로드·URL 발급, 로그인/로그아웃/계정 상태만 요청한다. 키·토큰은 JS로 보내지 않는다. 네이티브 주 프레임의 파일 URL 메시지만 받으며 계정 변경 뒤 늦게 도착한 결과는 버린다.
- 웹 전용 Supabase SDK는 앱 번들에서 제거한다. 웹은 `oi-web-config` Edge Function에서 공개 anon 설정만 받는다. 해당 함수는 정확한 웹 Origin만 허용하되, 사용자 인가의 경계는 DB/Storage 권한이다.
- 폴링이나 이미지 선로딩을 하지 않는다. 카드 선택 140ms 후 현재 상태를 재조회하며 떠난 카드 요청은 UI를 덮어쓰지 않는다. 서명 URL은 메모리에 180초 캐시한다. 카드 렌더는 제출 때만 실행한다.
- 검토한 웹 모듈 7개를 `tools/education-experience/shared/`에 보존하고 원본과 불일치하면 앱 내보내기를 중단한다. 공식 이야기와 승인된 사용자 이야기를 같은 서버 피드에서 읽고 별도 가상 예시를 섞지 않는다. 실제 인물 자료는 앱 번들·Git에 포함하지 않는다.

## 공식 이야기와 공통 피드 후속 — 2026-11-16

웹의 공식 자료 9개와 앱의 별도 가상 자료가 달랐던 문제를 해결한다. 이미 웹에서 공개하던 원문 요약·사진·출처·이름·소속·날짜를 Supabase Storage의 **공개 참고 자료 전용** `oi-education-reference` 버킷으로 옮겼다. `catalog-v1.json`은 버전·원본 해시·공식 이야기 배열을 담고, 사진은 `postech-<원문 번호>/<SHA256>.webp`로 제공한다. 업로드된 자료는 관리자 CLI로만 관리하며 일반 사용자에게 쓰기·수정·삭제 정책을 부여하지 않았다. 이 공개 버킷에 사용자 작성 글·사진·카드를 넣지 않는다.

앱·웹의 같은 서비스가 공식 목록과 기존 `oi_education_stories`의 승인된 사용자 이야기 전체 페이지를 읽는다. 요청당 최대 50개이며, 첫 페이지 이후도 읽어 오래된 카드를 조용히 제외하지 않는다. 공개 목록을 더 보기로 탐색해도 구슬의 별도 공통 피드 순서는 변하지 않는다. 운영자에게만 허용되는 신고 필드는 공통 표시 DTO에서 뺀다. 공식 이야기는 사진·소속·본문과 원문 출처를 함께 표시하고, 사용자 이야기는 동일한 서버 카드 앞·뒷면을 표시한다.

작성자는 어느 쪽에서 저장하든 같은 계정의 ‘내 이야기’에서 초안을 이어 쓴다. 운영자 승인 후 양쪽 구슬에 함께 나타난다. 공개 검토를 건너뛰거나 기기 시연 자료를 자동 공개하지 않는다. 브라우저 전경 복귀·앱 재활성화·흩어보기 진입 때 공통 피드를 다시 읽으며 중복 요청을 묶는다. 타이머 폴링이나 드래그마다의 서버 요청은 추가하지 않는다. 연결 실패 시 상태를 안내하고 가상 사연으로 대체하지 않는다.

운영 적용: `20261116073000_oi_education_reference_catalog.sql`과 이력만 원자적으로 추가했다. 사용자 미디어 버킷은 비공개로 보존했다. 공식 이야기 9개와 사진 9장의 실제 HTTP 응답·CORS 및 업로드 전후 SHA-256 일치를 확인했다. 앱·웹용 동일 서비스로 운영을 각각 조회한 결과 9개 공식 이야기가 일치했다. 일반 사용자 업로드·설정 변경 차단은 격리 DB 두 이력과 운영 rollback으로 확인했다. 운영 DB의 RLS가 UPDATE를 0행 처리하는 경우도 오류로 차단하는 경우와 함께 검증한다. 실제 인물 데이터는 마이그레이션·문서·테스트에 복사하지 않았다.

검증: 공통 피드·출처/사진 경로 검증·51개 공개 이야기 페이지·계정 변경 뒤 응답 폐기를 포함해 앱 Node 33개, 웹 Node 41개가 통과했다. 기존 초안·동의·양면 업로드·검토·계정 통합·탈퇴 정책 검사도 유지한다. 실제 WebKit에서 공통 서버 목록의 가상 검사 자료가 표시되고 사진을 네이티브 계정의 초안에 저장하는 것을 확인했다. 실제 사용자 OAuth 완료·운영자 실승인·실기기 FPS는 별도 확인 대상이다.
