# 기부 증빙 종료 — #258

2026-11-09 결정. 공식 POSTECH 기부처 링크를 안내한다. 앱에서 입금 내역이나 영수증을 새로 받지 않으며, 운영자 검토와 사용자·운영자 AI 검사를 종료한다. 이야기·사진의 공개 검토, 신고·차단, 별도 학교 자료 확인은 유지한다.

- 본 앱은 로그인이나 목록 새로고침 때 기부 증빙을 가져오지 않는다. 과거 기기 자료는 해당 계정에 보관하며 탈퇴 시 지운다.
- 서버는 이전 버전의 시작·제출·재제출·검토 RPC와 `oi-evidence` 파일 업로드·덮어쓰기를 차단한다. 이전 AI 함수 주소는 HTTP 410을 반환하며 원본 조회나 OpenAI 호출을 하지 않는다.
- 이미 접수한 증빙 원본·이력과 해당 계정의 기존 작성 승인 연결은 일괄 변경하지 않는다. 공개 열람을 허용하지 않으며 기존 보관 기준과 탈퇴 시 삭제를 적용한다.

## 운영 적용 순서

1. #258을 병합한 코드에서 대상 프로젝트가 기존 52gibu인지 확인한다. 사용자·운영자 기부 AI 경로를 먼저 종료한다. 기존 JWT 검증 설정을 유지하고 학교 자료 함수의 환경은 그대로 둔다.

   ```sh
   supabase functions deploy analyze-donation-evidence --project-ref kfzfzarslqdqmrazohej
   supabase functions deploy analyze-evidence --project-ref kfzfzarslqdqmrazohej
   ```

2. 운영 마이그레이션 이력을 확인하고 `20261109010000_oi_retire_donation_evidence.sql`을 기존 운영 배포 절차로 적용한다. 적용 후 이력에 해당 버전이 기록됐는지 확인한다. 증빙 테이블·버킷·보관 자료를 삭제하지 않는다.
3. 일반 테스트 계정으로 기존 시작·제출·재제출 RPC와 두 AI 함수가 410을 반환하고 업로드가 거부되는지 확인한다. 운영자 테스트 계정에서 이전 검토 RPC도 410인지 확인한다. 원본이나 실제 기부자 정보는 요청에 넣지 않는다. 별도로 일반 계정의 이야기 작성 → 사진 첨부 → 검토 요청 → 운영자 승인 → 다른 계정에서 이야기·사진 조회와 신고·차단을 확인한다.
4. 웹의 기부 안내, 최종 앱의 [스토어 설명·심사 메모](app-store/submission-copy.md)와 [개인정보 처리방침](../README.md#개인정보-처리방침)을 같은 변경으로 반영한다. 스토어의 개인정보 항목은 남은 실제 수집 경로와 기존 자료 보관 범위를 대조해 확인한다. 최종 `main`의 새 빌드를 팀 배포 서명으로 검증한다.
