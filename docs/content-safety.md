# 콘텐츠 신고·차단 — #197 (2026-11-06)

## 구현 범위

공개 이야기 상세·공유 링크·수집 카드에서 신고와 작성자 차단을 제공한다. 로그인한 본 앱에서는 `oi_report_content`로 신고를 접수한다. 비로그인·App Clip에서는 `8enchMark666@gmail.com`으로 신고 메일 작성을 열며, 직접 전송하기 전에는 접수됐다고 표시하지 않는다. 메일 앱이 없으면 주소·이야기 ID를 복사할 수 있다. 기부 증빙·연락처 등 민감정보는 첨부하지 않도록 안내한다.

작성자 차단은 기기 범위다. App Group에 작성자 UUID와 표시 이름을 저장하고 본 앱·Clip 목록, 상세 링크, 수집 카드, 공개 AR 조회에서 숨긴다. 원본 수집 기록을 삭제하거나 다른 기기에 동기화하지 않는다. 설정과 Clip 하단의 차단 관리에서 되돌릴 수 있다. 기기 저장소 읽기에 실패하면 기존 메모리 상태와 저장 자료를 덮어쓰지 않고 오류를 알린다.

## 운영자 처리

기존 운영자 공개 사전 검토를 유지한다. MY → 설정 → 운영자 관리 → 콘텐츠 신고에서 접수 내용을 읽고 사유를 남겨 종결·게시물 비공개·작성자 공개/작성 제한을 적용한다. 신고 테이블은 외부에 공개하지 않고 운영자 검사 RPC로만 읽는다. 작성자 제한은 다른 공개 이야기도 공개 조회에서 제외하며 새 작성·수집을 차단한다. 계정 통합 시에도 구성원 매핑을 따라 제한을 유지한다. 제한 해제는 해당 작성자의 명시적으로 비공개 처리한 글을 자동 공개하지 않는다.

서버는 같은 사용자·이야기 신고 재시도를 동일 영수증으로 처리한다. 1일 20건은 남용 방지 기술 제한이다. 이미 처리한 신고에 중복 결정을 내리면 충돌을 반환한다. 신고 내용과 운영자 화면은 비공개 자료로 취급한다. 신고·제한 자료는 연결 계정/이야기 삭제 시 외래 키 규칙에 따라 제거된다. 별도의 법적 보관 기간이나 자동 삭제 기간은 임의로 확정하지 않는다.

## 출시 전 운영 준비

- `20261106150000_oi_content_safety.sql`을 검토한 뒤 운영 DB에 적용해야 한다. 이 작업은 로컬 임시 DB 검증만 수행하며 운영 서버에 배포하지 않는다.
- 팀이 신고 메일과 운영자 신고 목록을 확인할 담당자·응답 절차를 지정해야 한다. 앱은 이메일을 자동 접수함에 옮기지 않는다. 이메일 신고는 기존 이야기 검토의 비공개 기능으로 대응할 수 있으며 작성자 제한은 운영자 신고 접수 건에서 수행한다.
- 실제 운영 계정으로 신고 → 검토 → 비공개/제한 → 공개 조회 차단을 확인한다. 실기기 App Group 공유와 메일 앱 연결도 확인한다.
- App Clip 공개 이야기/AR 변경(#199, PR #202)을 선행 적용한다. Apple 심사 통과나 운영 대응 완료를 코드 검사만으로 보장하지 않는다.
